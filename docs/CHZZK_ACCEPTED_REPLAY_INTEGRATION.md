# 승인한 오프라인 UI의 녹화본 연결

2026-09-13. 기존 원본 플레이어·채팅 로컬 테스트를 녹화보관함의 ‘앱에서 다시보기’에 연결한다. 실제 라이브 수신·계정·녹화 방식은 변경하지 않는다.

## 체크포인트

`checkpoints/chzzk-offline-player-2026-09-13T09-09-06-262Z`에 통합 전 승인 상태를 보관했다. 312개 파일, 55,430,074바이트이며 원본/복사본 SHA-256이 일치한다. 독립 실행 묶음, 재생성 소스·로컬 입력과 파일별 해시가 있다. 사용자 녹화·채팅·DB·쿠키는 포함하지 않는다. 이 폴더는 Git에서 제외되지만 빌드 출력처럼 자동 정리하지 않는다. 복원은 내부 README를 따라 수동으로 한다.

## 연결 경계

- `publish-app.mjs`는 이미 확보된 원본 131개 자산과 승인된 표현식을 로컬에서 검증·생성한다. 모든 공개 JS 모듈의 구문도 검사한다. 원본 바이트는 보존하고, 앱 채팅에 적용하는 파생 CSS의 주소만 로컬화한다. 사용하지 않는 외부 폰트 대체 경로는 비활성화한다.
- 영상은 기존 opaque iframe + 전용 정적 자산 프로토콜을 사용한다. 영상 파일은 녹화 ID로 발급한 기존 세션 토큰을 통해서만 읽는다. 원본 SDK의 온라인 앱 진입점이나 계정 코드는 불러오지 않는다.
- 방송 정보는 원본 상세 헤더 표현식과 `header_info` 슬롯을 그대로 사용한다. 실제 저장 제목과 녹화 시작 시각을 넣고, 표시·숨김은 원본 플레이어가 담당한다. 녹화본에 LIVE 배지·현재 시청자·실시간 업타임은 만들지 않는다. 과거 저장 데이터에는 채널명이 별도로 없으므로 추측하지 않고 해당 줄을 생략한다.
- 제목 갱신·채팅 검색·시간 보정·넓게 보기로 영상 iframe이나 미디어 소스를 재생성하지 않는다. 개인정보 가리기와 세션 종료 시 재생 중지·토큰 폐기는 유지한다.
- 채팅은 승인된 원본 LIVE 외곽/헤더/목록과 원본 메시지 표현식을 ShadowRoot에 연결한다. 저장된 본문·색상·배지 등의 기존 안전한 데이터 바인딩을 유지한다. 원본 전송/후원 영역 대신 승인된 검색 입력창을 사용한다.
- 원본 UI와 스타일 묶음은 녹화본을 열 때 지연 로드한다. 다른 탭의 첫 로딩에 전체 원본 CSS/채팅 표현식을 포함하지 않는다.

## 저장 채팅 검색

본문 또는 닉네임의 문자열 포함 검색이다. NFKC·대소문자·연속 공백을 정규화하며 정규식/SQL 표현식은 실행하지 않는다. 전체 로그를 로컬 파생 인덱스에서 검색하고 결과는 최대 200개, 화면은 최대 80행씩 표시한다. ‘n개 표시’는 현재 받은 결과의 수이며 전체 검색 건수로 오해시키지 않는다.

파생 인덱스 버전은 4다. 이전 인덱스는 필요할 때 다시 생성하며 원본 영상·채팅 로그는 수정하지 않는다. 검색은 백엔드 작업에서 실행하고, 이전 요청은 세대 번호와 SQLite 중단 검사로 취소한다. 커서는 녹화 세션·검색어·검색 범위에 묶인다. 입력은 최대 256자다. 검색 중에도 영상은 계속 재생된다. 결과의 시각 이동 버튼을 누르면 해당 영상 시점으로 이동하고 재생 위치 채팅을 다시 따라간다. Escape는 검색만 지우며 플레이어를 닫지 않는다.

## 검색 단순화·영상 우선 배치 (2026-09-14)

- 대상은 녹화본 다시보기다. 검색창 위 전체·본문·닉네임 버튼과 재생 위치 상태줄을 제거했다. 입력 하나로 본문과 닉네임을 함께 검색한다. 결과 수는 스크린리더용 안내에만 남기고, 기존 검색 지우기/Escape/결과 시점 이동은 유지한다. 로컬 시제품과 앱 자산을 같은 생성 소스로 갱신했다.
- 기존 고정 1600×920 상한은 영상 비율과 무관했다. 실제로 918px 높이 영역에 약 541px 영상을 넣어 약 377px의 여백이 생겼다. 이제 화면 크기와 원본 SDK가 전달한 실제 영상 비율로 최대 표시 크기를 계산한다. 기본 바깥 여백은 18px(작은 창 6px), 넓게/전체화면은 0px다.
- 읽을 수 있는 우측 채팅과 하단 채팅 배치를 비교한다. 하단 배치가 영상을 2% 이상 크게 표시하거나 우측 채팅이 너무 좁고 낮을 때 하단으로 옮긴다. 하단에서는 영상에 필요한 높이를 먼저 확보하고 남은 높이를 채팅에 배정한다. 영상 자르기, 왜곡, 임의 확대/줌은 하지 않는다.
- 상태 안내는 별도 오버레이여서 나타나거나 사라져도 영상 크기가 바뀌지 않는다. 전체화면도 영상과 채팅을 함께 보존한다. 영상에 이미 들어 있는 검은 띠나 영상·채팅을 함께 놓을 때 생기는 화면 바깥 잔여 공간은 자르기 없이 모두 없앨 수는 없다.
- 배치 계산은 다시보기가 열려 있을 때만 창 resize를 프레임당 한 번 처리한다. DOM 크기를 읽고 쓰는 반복 루프나 이미지 연산이 없다. 다른 탭에는 새 리스너를 설치하지 않는다. 창 크기/채팅 설정/검색/넓게 보기 변경으로 iframe·미디어 소스는 재생성하지 않는다.

검증: 검색·채팅·원본 플레이어·배치 회귀 77개 통과, 마지막 배치 보완 후 관련 30개와 타입 검사 재통과, 로컬 원본 자산 검증 12개 통과. 360개 화면/영상 비율/확대 상태 조합에서 잘림·왜곡·범위 초과를 검사했다. 프런트엔드 빌드와 2849 개발 실행 파일 빌드도 통과했다.

실제 합성 영상 렌더링에서 1280×720은 약 969×545, 1920×1080은 1529×860, 3440×1440은 약 2492×1402, 600×900은 586×330 영상과 하단 채팅으로 표시됐다. 영상 영역과 프레임 사이 추가 여백은 반올림 오차 0.02px 이하였고, 창 변경 중 iframe은 유지됐다. 닉네임 통합 검색 결과, 검색 중 재생, 검색 해제, 넓게 보기, 채팅을 포함한 전체화면도 확인했다. 원본 영상·채팅·계정 데이터와 라이브 녹화 수신 코드는 변경하지 않았다. 커밋·푸시·릴리즈는 수행하지 않았다.

## 확인 범위

### 채팅 메뉴·프로필 보완 (2026-09-13)

- 원본 CSS의 `:root` 토큰은 ShadowRoot에서 적용되지 않으므로 파생 스타일에서만 `:host`로 바인딩한다. 원본 파일과 체크포인트는 변경하지 않는다. 고정 353px 채팅 너비는 앱의 실제 열 너비에 맞추고 헤더/검색 영역 경계를 복원한다.
- 별도 상단 도구줄은 제거한다. 닫기는 영상 우측 상단, 시각 표시·채팅 시간 보정·전체 로그는 원본 채팅 우측 메뉴 슬롯에 배치한다. 메뉴는 불투명 배경과 독립 겹침 순서를 사용하며, 보정 성공 후 닫히고 실패 시 입력을 유지한다. 미디어/iframe 크기·재생 상태는 바꾸지 않는다.
- 새 녹화의 native begin 시에만 공개 채널 정보(`/service/v1/channels/{id}`)를 한 번 요청한다. [프로토콜 참조](https://github.com/kimcore/chzzk/blob/main/src/client.ts). 기존 제한된 이미지 작업 큐를 사용하며 계정 쿠키를 전달하지 않는다. 일반/원본 녹화와 마도 모드가 같은 시작 경로를 거치며 채팅 저장 OFF여도 실행된다.
- 녹화 폴더의 `channel-profile.json`에는 채널 ID·이름·불투명 이미지 ID만 저장한다. 검증한 PNG/JPEG/WebP/GIF 사본은 `replay-assets`에 저장한다. 고정 API/이미지 호스트, 요청 시간, 크기·프레임·해상도 제한, 파일 해시 검증, 재분석 지점 차단, 덮어쓰기 금지를 유지한다. 실패는 녹화를 중단하지 않는다.
- 다시보기 open은 해당 녹화 폴더의 검증한 이미지만 읽어 원본 방송정보 UI에 전달한다. 토큰 프로토콜 또는 iframe의 네트워크 권한을 확대하지 않고 inline raster를 사용한다. 외부 URL/SVG는 거부한다. 이전 녹화는 소급 조회하거나 수정하지 않으며 저장 이미지가 없거나 손상되면 기본 프로필로 표시한다.

합성 자료로 원본 자산·HTML·CSP·채팅 검색·세션/파일 권한·개발 빌드를 검증한다. 실제 녹화본은 같은 녹화보관함 경로에 연결되지만, 검증을 위해 사용자 계정에 로그인하거나 실제 녹화를 시작하지 않는다. 원본 공개 자산의 로컬 보존은 재배포 허가를 뜻하지 않으며, 이번 작업에서 커밋·푸시·릴리즈는 수행하지 않는다.
