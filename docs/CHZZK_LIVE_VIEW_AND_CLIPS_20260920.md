# 라이브 시청·자동녹화 시청·클립 동작

2026-09-20, 공유 작업공간 2849 기준. 이번 변경은 공식 클립 팝업 연결과 시청 종료 아이콘이다. 수신·재생 분리나 녹화 시간축 변경은 하지 않았다.

## 두 시청 경로

- **라이브에서 링크 열기**: 일반 라이브용 WebView를 생성하거나 해당 페이지로 이동한다. 이 동작 자체가 녹화 시작은 아니다. 같은 채널의 자동녹화 수신기가 이미 따로 돌아가더라도 이 경로는 그것을 찾아 재사용하지 않으므로 두 개의 수신기가 생길 수 있다.
- **자동녹화 목록의 실시간 보기**: 채널과 녹화 ID에 해당하는 기존 수신기를 찾는다. 백그라운드 자동 수신기라면 화면 표시 권한(lease)만 연결하고 기존 WebView를 화면 안으로 배치한다. 새 페이지 이동·영상 재연결·새 녹화 파일 생성은 하지 않는다. 이미 일반 라이브나 마도 플레이어가 녹화하고 있다면 해당 화면으로 돌아간다.
- 두 경로는 `OfficialBrowserPanel`과 같은 플레이어 조작 UI를 사용한다. 기존 자동 수신기에 붙은 화면에서는 채널 교체·그리드 재연결·마도 전환을 막아 녹화 중인 수신기를 교체하지 않도록 한다. 녹화 중지·스크린샷·채팅 등은 현재 연결된 수신기를 대상으로 동작한다.
- **실시간 보기 종료**: 시청 화면과 소리만 닫는다. 자동 수신기는 다시 화면 바깥에서 재생·저장을 유지한다. **녹화 중지**와는 다르다. 녹화 중지를 직접 누르면 실제 녹화를 마무리하고 이번 방송의 자동 재시작을 억제한다.
- 자동 수신기를 시청 중일 때에는 사용자의 일시정지·음량 선택을 존중한다. 백그라운드 수신 상태로 돌아가면 약 3초 간격 점검으로 음소거·재생 유지가 적용된다. 단순한 탭 이동과 시청 종료는 별개의 동작이다.

## 배속·정지의 영향

현재 배포 코드에서는 재생 출력 재인코딩을 사용하지 않는다. 공식 플레이어가 이미 받은 압축 영상/음성 조각을 MSE에 넣는 순간 복사하고, 원본 미디어 시간축으로 저장한다. 별도 영상 다운로드는 없다.

- **음량/음소거**: 듣는 소리만 바뀐다. 녹화 파일의 원본 음성은 유지된다.
- **0.5~2배 시청/1.2배 따라잡기**: 원본 녹화 속도를 바꾸지 않는다. 버퍼가 부족하거나 최신 지점에 가까워지면 시청 배속을 되돌릴 수 있다. 배속 변경 자체로 녹화를 종료하지 않는다.
- **일시정지**: 정지 이벤트 자체는 녹화 중단 사유가 아니다. 압축 조각이 계속 도착하면 저장도 계속한다. 그러나 공식 플레이어가 버퍼를 채운 후 수신을 멈추면 더 저장할 데이터가 없어진다. 마지막 append 후 15초가 지나면 수신 대기로 표시하며, 녹화 세션이 열려 있는 것과 영상이 계속 저장되는 것은 다르다.
- **느린 배속/장시간 정지/되감기**: 수신이 재생에 종속되어 있으므로 계속 최신 방송을 빠짐없이 저장한다는 보장은 없다. 소스/코덱 변경이나 실제 시간축 누락·역행은 오류로 종료될 수 있다. 수신되지 않은 구간을 만들어 채우지는 않는다.
- **채팅**: 소켓 연결이 유지되는 동안 화면 정지와 별개로 메시지를 저장한다. 현재 싱크 관측에는 재생 중인 화면 시각도 포함되므로, 장시간 정지 중 받은 채팅이 같은 영상 시점에 몰리거나 되감기 시 원래 방송 시점과 어긋날 가능성이 있다. 수신과 표시의 시간축을 분리하는 후속 설계에서 함께 다뤄야 한다. 이번 요청에서 조용히 시간축 규칙을 변경하지 않았다.

관련 구현: `browser_host.rs::open`, `browser_auto.rs::auto_target`, `browser_auto_watch.rs::open_auto_watch/close_auto_watch`, `browser_auto_view.js`, `browser_encoded_capture.js`, `browser_page_chat.js::observeClock`, `replay_index.rs::observed_media_time`.

## 클립 팝업 변경

공식 공개 스크립트에서 현재 요청을 확인했다.

- 주소: `https://chzzk.naver.com/clip-editor?contentType=live&contentId=<liveId>&offsetTime=<시점>`
- 창: `chzzkClipEditor`, 초기 크기 1020×690.
- 일반 라이브에서는 기존 코드가 클립을 계정 창으로 오인했다. 계정 창은 녹화 중 생성이 제한된다. 자동 수신기와 마도에서는 채팅 팝업만 허용해서 클립 창을 거절했다.
- 새 경로는 녹화 컨트롤러와 분리된 **공식 편집기 창**을 연다. 기존 브라우저 로그인 프로필과 opener를 사용하되 계정 작업으로 예약하지 않고 녹화 코드도 넣지 않는다. 공식 페이지가 직접 처리하는 로그인 여부·채널의 클립 허용 조건은 바꾸지 않는다.
- HTTPS/정확한 공식 호스트/편집 경로/라이브 ID/유한한 시점만 허용한다. 다른 사이트, 중복·알 수 없는 URL 인자, 계정 페이지나 다른 방송으로의 이동은 거절한다. 숨겨진 자동 수신기에서는 편집기를 열 수 없다.
- 프라이버시 모드에서는 클립 창도 숨김·음소거하고 로그아웃 시 닫는다. 클립 페이지에는 앱 파일 권한이나 녹화 브리지가 없다.
- 공식 코드 자체가 클립 창을 여는 동안 원래 라이브 플레이어를 음소거하고, 창을 닫으면 복구한다. 이는 원본 녹화 음성을 지우지 않는다. **편집기 미리보기에는 별도 영상 요청이 발생할 수 있다.** 평소 시청+녹화의 단일 수신과 구분해야 한다.
- 클립 만들기/게시 버튼의 대리 클릭이나 실제 게시 작업은 하지 않았다. 녹화본 로컬 잘라내기 기능을 새로 만든 것도 아니다.

공식 참고: [클립 이용 안내](https://help.naver.com/service/30044/contents/23258?lang=ko), [확인한 공개 플레이어 스크립트](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-DdGx9_UO.js), [공식 클립 편집기 스크립트](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/clipEditor-DlT1b68-.js).

## 시청 종료 버튼

별도 음소거처럼 보이던 스피커 아이콘을 **화면 밖으로 나가는 화살표**로 변경했다. 이름은 **실시간 보기 종료**, 툴팁은 **실시간 보기 종료 · 시청 화면과 소리만 닫고 녹화는 계속합니다**. 원래 음량 버튼과 녹화 중지 버튼은 유지한다.

## 검증 범위

- 프런트엔드 관련 220개 테스트 통과: 공식 조작 UI, 자동녹화 시청 전환, 일반 시청·마도, 원본 저장, 채팅 경로.
- 네이티브 스트리밍 322개 테스트 통과, 기존 환경 의존 6개 제외.
- TypeScript 검사, 프런트엔드 및 개발 실행 파일 빌드 통과. 최종 프라이버시 전환 방어 반영 후 클립 정책 3개 테스트와 실행 파일 빌드를 재확인했다.
- 실제 로그인한 계정에서 클립 편집 완료/게시는 실행하지 않았다. 실제 앱을 켜면 자동녹화가 시작될 수 있어 이번 검증에서는 앱과 실사용 녹화 데이터를 열거나 변경하지 않았다.
- 수신기 독립화, 장시간 일시정지 중 무누락 보장, 채팅 싱크 기준 개선은 이번 변경 범위가 아니다.
