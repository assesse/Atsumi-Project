## 이번에 구현한 범위

### 시청 화면

2026-09-12 추가 정리: 기본 시청도 제목·상태·녹화·고화질 연결·시청/마도 버튼 행을 영상 바깥에 두지 않는다. 공식 LIVE 옆 gear의 설정에서 로그인·고화질 연결·마도에 접근한다. 초기 연결 화면과 설정창은 stage 안에 겹쳐 표시하므로 열거나 닫아도 영상 영역 높이는 바뀌지 않는다. 네이티브 영상 위에 부모 DOM을 단순히 덮지 않고 설정/권리 확인 동안에는 네이티브 표시를 가리며 녹화 수명은 유지한다. 구형 HLS 연결·수신·플레이어/API·보관함 UI는 제거했고 기존 영상·채팅 파일은 삭제/이관하지 않았다. hls.js는 압축 녹화 합성 fixture 생성용 개발 의존성으로만 남는다.

자체 `간단히 보기`/`전체 보기` UI와 단일 시청 presentation 스크립트를 제거했다. 공식 플레이어의 넓게/좁게 버튼·기존 클릭 동작을 그대로 사용한다. 설정 gear만 가능한 공식 LIVE 컨테이너의 안정적인 형제로 붙이고, 공간이 부족하면 영상 안의 비겹침 위치를 사용한다. LIVE의 상태 의미/클릭을 바꾸지 않는다. 녹화는 빈 중앙의 이중 원, 녹화 중에는 정지 사각형으로 구분한다. 설정 요청은 파일 권한을 부여하지 않으며 만료·채널·페이지 세대로 늦은 요청을 폐기한다.

단일 시청의 영상·중간 wrapper·채팅 폭/높이를 정규화하던 자체 CSS 재배치는 더 이상 주입하지 않는다. 광고/본방 교체와 공식 대화상자의 크기·표시는 사이트가 맡는다. 마도 전용 pane 배치 스크립트는 별도로 유지한다. gear/녹화 도구 삽입을 위해 공식 영상·채팅 DOM을 재생성하지 않는다.

녹화 시작 때 채널명·시간·저장 용량·보관함 행이 나타나 flex 영역을 줄이던 구조를 수정했다. 시청 중에는 상태 배지의 크기를 고정하고 자세한 정보·오류는 도움말에 표시한다. 보관함 목록은 보관함 화면에만 표시한다. 넓게 보기에서도 녹화 시작·중지·실패·스크린샷 완료 때문에 영상/채팅 영역 크기가 바뀌지 않는다. 작은 창에서는 최소한의 읽기 가능한 높이를 유지하며 스크롤로 접근한다. 원본 영상 비율을 보존하므로 공간 비율에 따른 여백까지 항상 없애는 기능은 아니다.

공식 플레이어 하단 버튼 영역에 녹화·화면 저장·따라잡기 버튼을 배치했다. 공식 버튼 영역을 찾지 못하면 플레이어 안쪽에 호버/키보드 포커스 때 나타나는 작은 도구 모음을 사용한다. 자체 원본 페이지 전환 버튼은 제거했다. 사이트 DOM에 의존하므로 사이트 업데이트 후 위치 확인이 필요하다.

녹화 동의는 시작 확인창에서 받는다. `S`는 현재 방송의 화면 저장을 요청하지만 단일 시청의 공식 넓게/좁게·Esc 동작은 가로채지 않는다. 마도에 필요한 자체 나가기만 유지한다. 채팅 입력·편집 중이거나 확인창이 열렸을 때에는 저장 단축키가 끼어들지 않는다. 저장은 승인 후 프레임을 캡처하므로 `S`를 누른 바로 그 프레임을 보장하지 않는다.

원격 페이지 버튼은 **요청만** 보낸다. 파일 저장·녹화 권한은 Atsumi 확인창에서 다시 승인해야 한다. 요청은 채널·페이지 세대·만료 시간에 묶이며, 취소가 기본 포커스다. 화면 저장은 영상 한 프레임의 PNG이며 채팅/플레이어 버튼을 포함하는 전체 창 캡처가 아니다. 저장 위치는 다운로드 루트의 `CHZZK/Screenshots`다. 이미지 크기·전체 바이트·조각 크기·대기열 제한, PNG 검증과 경로 검증을 적용했다. 실제 계정의 화면을 이번 검증에서 저장하지 않았다.

채팅 입력란의 placeholder/data-placeholder 변경을 제거했다. 긴 placeholder가 content 기반 자동 크기에 영향을 줄 수 있어 입력 높이/스타일도 건드리지 않는다. 합성 Edge에서 이전 길이의 placeholder로 높이가 늘어나는 양성 대조와 수정 후 focus/blur 높이 유지를 확인했지만 실제 CHZZK의 autosize 구현까지 같은 원인이라고 실측 확정한 것은 아니다. 끝점까지의 거리는 따라잡기 버튼 도움말에 표시한다. `seekable`의 끝과 현재 재생 위치 차이를 사용하며 없으면 `buffered`를 확인한다. **송출부터 화면까지의 총 지연이 아닌 플레이어가 알려주는 끝점과의 거리**이며 측정 불가를 0초로 표시하지 않는다.

UI 배치는 [Cheese-PIP 녹화 버튼](https://github.com/khk4912/Cheese-PIP/blob/main/src/components/record/RecButton.tsx), [화면 저장 버튼](https://github.com/khk4912/Cheese-PIP/blob/main/src/components/screenshot/ScreenshotButton.tsx)의 공식 컨트롤 영역 사용 방식을 참고했다. 끝점 거리 지표의 초기 참고는 [CHZZK Plus bufferDisplay](https://github.com/kyechan99/chzzk-plus/blob/main/src/feature/bufferDisplay.ts)지만 현재 입력란 표시 방식은 사용하지 않는다. 확장 전체를 복사하거나 설치하는 구현은 아니다.

### 마도 모드

시청 화면에서 `마도` → 최대 네 채널 주소 입력 → 배치 선택 → `적용`한다.

- `방송·채팅`: 각 방송과 그 채팅을 한 묶음으로 배치한다.
- `영상 하나·채팅 모아보기`: 선택한 영상 하나와 입력한 채널들의 채팅을 함께 표시한다.
- 처음에는 모두 음소거이며 각 방송의 소리를 독립적으로 켜고 끌 수 있다. 여러 방송을 동시에 켜도 된다. 공식 플레이어의 음량 조절은 그대로 사용한다. 배치 변경으로 다시 연결하면 모두 음소거로 돌아간다.
- 넓은 화면은 격자, 좁은 화면은 스크롤 배치다. 태그/앨범 탭의 레이아웃 상태와 공유하지 않는다.
- 각 영상 pane에서 녹화·화면 저장·`S`가 단일 시청과 같은 방식으로 동작한다. 녹화 저장소·종료 보호는 공유하며 최대 네 개의 녹화를 허용한다. 녹화/승인 대기 중 배치 변경과 창 닫기는 막는다. UI 새로고침·탭 이동은 녹화 중인 원격 pane을 숨길 뿐 녹화를 강제로 닫지 않는다.
- 방송 선택에는 `1. 채널명`을 표시한다. 공개 채널명 조회가 끝나기 전에는 번호가 먼저 보일 수 있다.
- 채팅 모아보기는 `위아래 배치`/`좌우 배치`를 선택하고 영상과 채팅 사이 구분선을 드래그하거나 방향키로 조절한다. 읽을 수 있는 최소 크기를 지키고 선택한 비율은 로컬에 저장한다.
- 로그인·고화질 확장 연결은 먼저 한 방송 보기에서 준비한다. 앱 재실행 직후에도 한 방송 보기에서 연결을 확인해야 할 수 있다.

같은 구성 재적용, 스크롤·뷰포트·음성 변경은 방송을 다시 로드하지 않는다. 구성 변경은 기존 시청을 닫고 새 구성을 만든다. 기존 단일 녹화 저장소/브리지를 여러 pane에 복제하지 않았다. 방송 화면 최대 4개, 영상·채팅 합계 최대 8개다. 채팅은 공식 `/live/{id}/chat` 전용 경로를 사용하고 전체 라이브 화면으로 fallback하지 않는다. 해당 경로는 [공식 배포 스크립트](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-C4sif-4p.js)의 채팅 팝업 생성 코드에서 확인했다.

채팅 pane의 native MEDIA 요청을 거부하지만 이것은 fetch/MSE/확장 연결 트래픽까지 완전히 차단하는 보장이 아니다. 1+4 배치는 한 영상만 생성하도록 설계했고, 실제 네트워크 계수 검증은 남아 있다. 네 영상을 선택하면 네 방송의 영상 트래픽이 필요한 것은 정상이며, 한 방송을 시청·녹화 때문에 두 번 받는 문제와 다르다.

모든 원격 pane은 일반 Tauri IPC 접근이 차단된다. pane epoch/요청 순서로 늦은 표시·종료 응답을 무효화하고, 프라이버시/앱 reload 시 즉시 숨김·음소거를 요청한다. 파일 작업 승인은 pane·채널·페이지 세대에 묶이며 다른 방송에 재사용할 수 없다. 정상 UI 호출은 직렬화/병합되지만 모든 native IPC worker 대기 수에 별도의 엄격한 상한을 구현한 것은 아니다.

## 배속과 압축 데이터 저장

공식 시청은 공식 페이지가 직접 재생한다. 녹화 파일의 저장 완료를 기다린 뒤 재생하지 않는다. 플레이어의 `따라잡기`는 1.2배로 재생해 알려진 끝점에 접근하고, 간격이 약 1초가 되거나 버퍼가 부족하면 원래 1배로 돌아온다. 순간 이동이나 별도 영상 요청을 하지 않는다. 사용자나 공식 플레이어가 다른 배속을 선택하면 그 값을 덮어쓰지 않는다. 이 기능은 송출/CDN 자체의 지연을 제거하지 않는다.

지원하는 경로에서는 **공식 플레이어가 이미 받은 압축 영상 데이터를 저장기로 분기**한다. 별도 HLS 다운로더를 동시에 켜지 않는다. 메인 창 MSE에 공급되는 암호화되지 않은 AVC/H.264 + AAC-LC fMP4만 대상으로 하며, 파일 컨테이너를 다시 구성하고 원래 영상·음성 샘플의 시간 정보를 보존한다. 이 저장 경로의 native 승인이 확인된 동일 영상에만 녹화 중 따라잡기를 허용한다. [MSE 규격](https://www.w3.org/TR/media-source-2/)의 worker 경로 등 모든 실행 방식을 지원하는 것은 아니다. DRM·권한 제한 우회나 키 추출은 포함하지 않는다.

1. 녹화하지 않을 때는 제한된 init 정보만 기억한다. URL·쿠키를 읽거나 기록하지 않는다. 원래 append를 그대로 호출하고 디스크 응답을 기다리지 않는다.
2. 녹화 큐는 64 MiB, native 조각은 128 KiB로 제한한다. 큐 초과·불연속·화질/코덱 변경·원본 교체 등 지원하지 않는 변화를 감지하면 중단을 표시하고 확정된 파일을 보존한다. 무제한 메모리 증가나 누락의 성공 처리를 하지 않는다.
3. 영상 키프레임 경계를 기준으로 약 12초 이후 독립 재생 파일을 마감한다. 시작 시 다음 키프레임까지 기다릴 수 있다. 재공급된 동일 조각은 중복 저장하지 않으며 원본의 샘플 간 시간 간격을 유지한다.
4. 시작 전 지원 불가가 확정되면 기존 1배속 화면 녹화로 돌아간다. 이미 녹화를 시작했거나 native 응답을 잃은 경우에는 두 번째 녹화를 몰래 시작하지 않는다. 기존 화면 재인코딩 중에는 따라잡기를 막는다. [미디어 요소 캡처 규격](https://www.w3.org/TR/mediacapture-fromelement/#html-media-element-media-capture-extensions)
5. 탐색/일시정지는 연속 수신을 보장할 수 없으므로 압축 데이터 녹화도 안전하게 중단한다. 이는 방송을 보지 않아도 독립적으로 계속 받는 다운로더가 아니다.

채팅은 기존 전체 로그를 유지한다. 저장한 `sourceStartSeconds/sourceEndSeconds`는 미디어 시간축이며 방송 업타임이나 UTC가 아니다. 초기 키프레임 대기와 수신 버퍼에 따라 채팅과 파일 사이의 기준점 차이가 생길 수 있다. 정확한 채팅 재생 동기에는 별도의 source↔UTC 기준 검증이 필요하며, 이번 구현이 이를 해결했다고 간주하지 않는다.

채팅 종료 응답은 최대 2초 기다린 뒤 영상 마무리를 우선한다. 저장 실패/누락 가능성은 작은 경고에 표시하고 `recording.json`에 보존한다. 과거 기록에 이 메타데이터가 없으면 완전 저장으로 추정하지 않고 확인되지 않은 상태로 표시한다. 보관함 경고 저장 자체가 실패해도 기존 영상은 삭제하지 않는다.

실방송 수용 기준은 여전히 별도 확인 대상이다: 녹화를 켜서 발생한 **추가 영상 다운로드 0**, 공식 단독 재생 대비 추가 지연 중앙값 100 ms/P95 250 ms 이내, 재버퍼링 증가 없음, 2시간 녹화·강제 종료 후 복구. 이 수치는 달성 결과나 방송의 절대 지연 약속이 아니다. 바이트 복사·컨테이너 처리의 CPU 비용이 목표를 깨면 해당 경로를 보류해야 한다.

## 검증 범위

단일 시청 상태 변화, 마도 배치/프라이버시/늦은 응답/음성 소유권/원격 IPC/화면 저장 입력 제한을 모의 입력과 단위 테스트로 검사했다. 실제 CSS 레이아웃을 여러 창 크기에서 검사했다. 실제 계정 로그인, 실제 네 방송 동시 고화질 재생, 장시간 녹화, 공식 사이트 업데이트에 따른 DOM 변동까지 검증한 것은 아니다.
