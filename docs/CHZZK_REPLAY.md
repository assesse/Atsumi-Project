# 저장 영상·채팅 함께 보기

2026-09-12 구현 명세. 작업 위치는 통합된 `2849`이며 구형 HLS 경로를 다시 사용하지 않는다. 구현 검증은 로컬 합성 자료 기준으로, 실제 계정·사용자 녹화의 검증이나 원본 재작성은 포함하지 않는다.

## 사용 방식

녹화 보관함에서 병합이 끝난 항목의 **앱에서 다시보기**를 누른다. 저장 영상과 읽기 전용 채팅이 함께 열리며, 외부 플레이어 열기는 보조 기능으로 남는다.

- 재생·정지, 위치 이동, 음량, 0.5/0.75/1/1.25/1.5/2배속. 전체화면에도 채팅이 함께 남는다.
- Space/K: 재생·정지, ←/→: 5초 이동, M: 음소거, F: 전체화면. 입력란에서는 단축키를 가로채지 않는다.
- 채팅 시각은 녹화 경과 / 방송 업타임 / 숨김. 미확인 업타임을 0초로 표시하지 않는다.
- 채팅을 위로 스크롤하면 따라가기를 멈추고 `현재 재생 위치로`로 복귀한다. `전체 로그`에서는 200개씩 이전·다음 기록을 읽는다. 200개는 저장 한도가 아니다.
- 톱니바퀴에서 녹화별 채팅 시간 보정을 저장한다. 양수는 채팅을 더 늦게 표시한다. 원본 메시지 시각은 바꾸지 않는다.
- 재생바 위 채팅 분포를 누르면 해당 시간대로 이동한다. 저장 메시지 수이며 시청자 수와 같지 않다.

다른 라이브 시청·녹화를 자동 종료하지 않는다. 저장본 디코딩은 추가 CPU/GPU·디스크 자원을 사용하며 프라이버시 모드에서는 저장본도 정지·가린다.

## 라이브 배속과 녹화 안전성

라이브 배속 메뉴도 제공하지만 저장 방식에 따라 동작이 다르다.

- 원본 압축 패킷을 보존하는 녹화는 네이티브가 현재 영상과 같은 소스로 확인한 경우 시청 배속을 바꿀 수 있다. 저장 타임스탬프 자체를 배속으로 바꾸지 않는다.
- 화면을 다시 인코딩하는 MediaRecorder 대체 경로는 녹화 중 1배속을 유지한다. 제한을 풀면 빨라진 화면·음성이 저장될 수 있다.
- 최신 위치를 따라잡아도 서버가 아직 제공하지 않은 프레임을 앞당기지는 못한다. 배속이 송출/CDN 지연을 없애거나 1초 지연을 보장하지 않는다.
- 별도 HLS 수신기를 추가하지 않는다. 시청 배속을 위해 같은 방송 영상을 이중 다운로드하지 않는다.

시각 필드·소스 검증·B-frame 기준은 [채팅 시간 기준](CHZZK_CAPTURE_CLOCKS.md)에 상세히 기록한다.

## 영상과 채팅의 시간 대응

채팅은 wall-clock 타이머가 아니라 저장 영상의 `currentTime`을 따라간다. 정지·버퍼링 때 진행하지 않고 뒤로 탐색하면 그 위치의 채팅을 다시 표시한다. 탐색 세대 번호가 지난 비동기 응답은 폐기한다.

새 녹화는 선택적 `replayClock`에 소켓 수신 시각, 단조 시각, 관측 영상 위치·배속, 소스 세대/ID를 저장한다. 네이티브 검증과 병합 구간 대응이 성립한 메시지만 `observed_media`다. PTS/DTS와 B-frame CTS를 같은 값으로 가정하지 않는다. 필드가 없거나 대응이 불명확하면 `receive_time_approximate`다.

병합 구간 원본 시작이 S, 병합본 시작이 M일 때 검증된 원본 영상 시각 s는 `M + (s - S)`로 대응한다. 기존 `offsetSeconds`는 녹화 후 수신 경과로 s에 바로 대입할 수 없다. `broadcastOffsetSeconds`도 업타임 표시용이지 미디어 시각이 아니다.

기존 자료는 수신 시각 근사와 수동 보정으로 시작한다. 버퍼·재접속·광고·캡처 회전 공백에 의한 구간별 차이를 단일 보정으로 모두 복구할 수 없다. 일부만 정밀 대응되는 기록을 전체 정밀 기록으로 표시하지 않는다. 송출 프레임과 채팅 작성자의 인과관계를 보장하지도 않는다.

## 저장과 긴 로그 처리

`chat.jsonl`, 원본 조각, 저널, 병합 타임라인을 보존한다. 파생 인덱스·보정은 앱 데이터의 `streaming/replay` 아래에 저장한다.

1. 녹화 ID로 소유 파일을 확인한다. 종료되고 검증된 병합본만 연다. 임의 경로·URL·미완성 파일은 받지 않는다.
2. 영상은 임시 토큰 기반 로컬 `atsumi-replay` 프로토콜로 읽는다. 전체 영상을 IPC/base64로 보내지 않는다.
3. 취소 가능한 별도 작업에서 JSONL을 순차 읽어 SQLite 시간/순서/사용자 인덱스를 만든다. 동일 녹화·파일 세대의 완성 인덱스를 재사용한다. 인덱스 손상 시 파생 파일만 재구축한다.
4. 응답은 최대 200행·1MiB, 한 JSONL 행은 64KiB, 렌더링은 최대 80행이다. 전체 로그를 React 상태에 쌓지 않는다. 시간 탐색은 완성 인덱스를 사용한다.
5. 동시 다시보기/인덱스 작업 최대 4개, SQLite 캐시 연결당 2MiB, 인덱스 개별 1GiB 제한과 누적 2GiB 개방 가드가 있다. 제한 때문에 원본을 삭제하지 않는다.
6. 잘린 줄·잘못된 레코드·중복 순서·시계 역행·원본 변경은 경고 또는 안전 오류로 처리한다. 닫기·앱 종료 시 작업을 취소·회수한다.

API: `replay_open`, `replay_close`, `replay_chat_at`, `replay_chat_page`, `replay_timeline`, `replay_set_offset`. 커서는 세션·소스 세대에 묶이며 탐색 세대도 별도로 검사한다. 공식 웹 페이지에는 이 파일/API 권한을 주지 않는다.

## 배지·이모티콘과 오프라인

공식 DOM을 저장하거나 재실행하지 않는다. 저장된 닉네임·허용 색상·배지·이모티콘으로 같은 **영상+채팅 사용 방식**을 재현한다. 후원 UI·로그인·채팅 전송·모든 공식 효과의 완전 복제는 아니다.

새 채팅 수신 때 허용된 공개 CDN의 꾸밈 이미지를 쿠키 없이 보조 저장한다. 한 작업자, 대기열 128개, 최대 4096파일/128MiB 예산이며 바이트·픽셀·형식·해시를 검사한다. 영상 수신과 별개의 소량 이미지 요청이다. 실패/상한 초과가 녹화·채팅 저장을 막지 않는다.

재생 중에는 외부 URL을 요청하지 않고 해당 녹화에서 확인된 로컬 이미지 ID만 허용한다. 누락은 배지명/이모티콘 문자로 대체한다. 과거에 저장하지 않은 이미지나 같은 URL의 사후 변경을 완벽히 복원할 수 없다. HTML/SVG/저장 스크립트를 실행하지 않는다.

## 검색·분석 확장 경계

이번 구현은 채팅 밀도 분포와 구간별 고유 참여자 수 기반을 포함한다. 다음 단계는 별도 계약으로 확장한다.

- 본문 검색: 동일 SQLite 인덱스에 버전형 FTS를 추가하고 결과를 현재 `seek`로 연결한다.
- 사용자 검색: 새 기록의 녹화별 salt 기반 `senderKey`를 이용한다. 원시 계정 ID·salt는 저장하지 않고 서로 다른 녹화 사이에서 같은 키라고 가정하지 않는다. 닉네임만 있는 과거 자료의 동일인 판별은 불명확하다.
- 시청자 추이: 신뢰할 수 있는 저장 수치가 없어 현재 `viewerMetricStatus=not_recorded`, `viewerCount=null`이다. 채팅 참여자 수를 시청자 수로 대체하지 않는다. 추후 신뢰 가능한 관측값이 있으면 버전형 metric 이벤트에 관측 시각, 소스/시간 기준, 값, 품질·누락 상태를 저장해 미디어 타임라인에 대응한다.
- 광고·재접속·시계 불연속: 시간 대응 품질을 별도 층으로 보여 채팅 급증과 수집 공백을 구분한다.
- SRT/ASS 내보내기: 선택적 파생 파일로 고려하되 앱의 배지·스크롤 채팅과 동일한 표현을 보장하지 않는다. 영상에 구워 넣거나 원본을 덮어쓰지 않는다.

전체 로그 탐색과 미래 본문/사용자 검색은 다르다. 아직 구현하지 않은 검색·시청자 수집을 완료된 기능으로 표시하지 않는다.

## 검증 범위

합성 수십만 행 로그, 앞뒤 탐색과 오래된 응답, 세션/파일 세대 변경, 인덱스 재사용·손상·취소, 악성 꾸밈 이미지, 소스/시계 위조와 B-frame 대응을 회귀 검증한다. UI는 합성 채팅과 로컬 영상으로 확인한다. 실제 방송·광고·네트워크 장애의 장시간 정확도 검증은 별도이며 사용자 자료를 자동 백필/삭제하지 않는다.
