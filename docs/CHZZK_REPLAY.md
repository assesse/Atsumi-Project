# 저장 영상·채팅 함께 보기

2026-09-12 구현 명세. 작업 위치는 통합된 `2849`이며 구형 HLS 경로를 다시 사용하지 않는다. 현재 다시보기는 공개 CHZZK 원본 PC 플레이어 SDK·VOD 슬롯·스타일시트를 로컬 격리 프레임에서 실제 실행한다. 앞선 자체 제작 조작부는 현재 재생 경로가 아니다. 구현 검증은 로컬 합성 자료 기준으로, 실제 계정·사용자 녹화의 검증이나 원본 재작성은 포함하지 않는다.

## 사용 방식

녹화 보관함에서 병합이 끝난 항목의 **앱에서 다시보기**를 누른다. 저장 영상과 읽기 전용 채팅이 함께 열리며, 외부 플레이어 열기는 보조 기능으로 남는다.

- 원본 플레이어의 재생·정지, 위치 이동, 음량, PIP, 설정과 0.25/0.5/0.75/1/1.25/1.5/1.75/2배속을 사용한다. 넓게 보기·전체화면은 Atsumi 영상+채팅 컨테이너로 연결한다.
- Space/K: 재생·정지, ←/→: 5초 이동, M: 음소거, F: 전체화면, T: 넓게 보기. 입력란에서는 단축키를 가로채지 않는다.
- 채팅 시각은 녹화 경과 / 방송 업타임 / 숨김. 미확인 업타임을 0초로 표시하지 않는다.
- 채팅을 위로 스크롤하면 따라가기를 멈추고 `현재 재생 위치로`로 복귀한다. `전체 로그`에서는 200개씩 이전·다음 기록을 읽는다. 200개는 저장 한도가 아니다.
- 상단 `채팅 시간`에서 녹화별 채팅 시간 보정을 저장한다. 원본 톱니바퀴는 플레이어 설정용이다. 양수 보정은 채팅을 더 늦게 표시하며 원본 메시지 시각은 바꾸지 않는다.
- 원본 재생바에 Atsumi의 구간별 채팅·시청자 분석 곡선을 덧붙인다. 관측되지 않은 시청자 수를 추정하거나 채팅 참여자 수로 대체하지 않는다.

다른 라이브 시청·녹화를 자동 종료하지 않는다. 저장본 디코딩은 추가 CPU/GPU·디스크 자원을 사용하며 프라이버시 모드에서는 저장본도 정지·가린다.

## 라이브 배속과 녹화 안전성

라이브 배속 메뉴도 제공하지만 저장 방식에 따라 동작이 다르다.

- 원본 압축 패킷을 보존하는 녹화는 네이티브가 현재 영상과 같은 소스로 확인한 경우 시청 배속을 바꿀 수 있다. 저장 타임스탬프 자체를 배속으로 바꾸지 않는다.
- 화면을 다시 인코딩하는 MediaRecorder 대체 경로는 녹화 중 1배속을 유지한다. 제한을 풀면 빨라진 화면·음성이 저장될 수 있다.
- 최신 위치를 따라잡아도 서버가 아직 제공하지 않은 프레임을 앞당기지는 못한다. 배속이 송출/CDN 지연을 없애거나 1초 지연을 보장하지 않는다.
- 별도 HLS 수신기를 추가하지 않는다. 시청 배속을 위해 같은 방송 영상을 이중 다운로드하지 않는다.

시각 필드·소스 검증·B-frame 기준은 [채팅 시간 기준](CHZZK_CAPTURE_CLOCKS.md)에 상세히 기록한다.

## 영상과 채팅의 시간 대응

채팅은 wall-clock 타이머가 아니라 원본 SDK가 재생하는 저장 영상의 `currentTime`을 따라간다. 격리 프레임은 `time`·`duration`·`paused`·`seeking`·영상 비율만 부모에 전달하고 부모는 출처와 유한한 값·범위를 검사한다. 정지·버퍼링 때 진행하지 않고 뒤로 탐색하면 그 위치의 채팅을 다시 표시한다. 탐색 세대 번호가 지난 비동기 응답은 폐기한다.

새 녹화는 선택적 `replayClock`에 소켓 수신 시각, 단조 시각, 관측 영상 위치·배속, 소스 세대/ID를 저장한다. 네이티브 검증과 병합 구간 대응이 성립한 메시지만 `observed_media`다. PTS/DTS와 B-frame CTS를 같은 값으로 가정하지 않는다. 필드가 없거나 대응이 불명확하면 `receive_time_approximate`다.

병합 구간 원본 시작이 S, 병합본 시작이 M일 때 검증된 원본 영상 시각 s는 `M + (s - S)`로 대응한다. 기존 `offsetSeconds`는 녹화 후 수신 경과로 s에 바로 대입할 수 없다. `broadcastOffsetSeconds`도 업타임 표시용이지 미디어 시각이 아니다.

기존 자료는 수신 시각 근사와 수동 보정으로 시작한다. 버퍼·재접속·광고·캡처 회전 공백에 의한 구간별 차이를 단일 보정으로 모두 복구할 수 없다. 일부만 정밀 대응되는 기록을 전체 정밀 기록으로 표시하지 않는다. 송출 프레임과 채팅 작성자의 인과관계를 보장하지도 않는다.

## 저장과 긴 로그 처리

`chat.jsonl`, 저널, 병합 타임라인을 보존한다. 새 녹화의 원본 영상 조각은 병합·전체 디코딩·해시 확인과 검증 기록의 저장까지 성공한 후 정리한다. 기존 완료 녹화는 일괄 삭제하지 않는다. [원본 조각 정리](BROWSER_RECORDING_CLEANUP.md)를 따른다. 파생 인덱스·보정은 앱 데이터의 `streaming/replay` 아래에 저장한다.

1. 녹화 ID로 소유 파일을 확인한다. 종료되고 검증된 병합본만 연다. 임의 경로·URL·미완성 파일은 받지 않는다.
2. 영상은 임시 토큰 기반 로컬 `atsumi-replay` 프로토콜로 읽는다. 전체 영상을 IPC/base64로 보내지 않는다.
3. 취소 가능한 별도 작업에서 JSONL을 순차 읽어 SQLite 시간/순서/사용자 인덱스를 만든다. 동일 녹화·파일 세대의 완성 인덱스를 재사용한다. 인덱스 손상 시 파생 파일만 재구축한다.
4. 응답은 최대 200행·1MiB, 한 JSONL 행은 64KiB, 렌더링은 최대 80행이다. 전체 로그를 React 상태에 쌓지 않는다. 시간 탐색은 완성 인덱스를 사용한다.
5. 동시 다시보기/인덱스 작업 최대 4개, SQLite 캐시 연결당 2MiB, 인덱스 개별 1GiB 제한과 누적 2GiB 개방 가드가 있다. 제한 때문에 원본을 삭제하지 않는다.
6. 잘린 줄·잘못된 레코드·중복 순서·시계 역행·원본 변경은 경고 또는 안전 오류로 처리한다. 닫기·앱 종료 시 작업을 취소·회수한다.

API: `replay_open`, `replay_close`, `replay_chat_at`, `replay_chat_page`, `replay_timeline`, `replay_set_offset`, `replay_open_profile`. 커서는 세션·소스 세대에 묶이며 탐색 세대도 별도로 검사한다. 프로필 열기는 토큰과 메시지 순서로 검증된 공개 주소만 조회하며 호출자가 임의 URL을 전달할 수 없다. 공식 웹 페이지에는 이 파일/API 권한을 주지 않는다.

## 실제 원본 플레이어와 격리 경계

`RecordingReplay`는 직접 `<video>`와 모사한 버튼을 만들지 않는다. `OriginalChzzkPlayer`가 `atsumi-player` 정적 프로토콜의 `frame.html`을 `sandbox="allow-scripts"` 프레임으로 열고, 그 안의 `runtime.js`가 CHZZK 원본 PC SDK **1.16.2**를 실행한다. `allow-same-origin`을 주지 않으므로 프레임의 origin은 `null`이며 부모 DOM·계정 쿠키·Tauri IPC에 접근할 수 없다. 실제 미디어 파일·채팅 인덱스·세션 권한은 기존 Atsumi 네이티브 경로에 남는다.

핵심 원본 API는 아래와 같다. 이것은 `runtime.js`의 소스 어댑터를 요약한 것이며 별도 생방송 수신기나 로그인 API가 아니다.

```js
import { S as loadPlayer } from './player-vendor-BYg0wCyN.js';
const P = loadPlayer();
const player = P.default.upgrade(document.querySelector('pzp-pc-layout'));
player.language = 'ko';
player.srcObject = new P.DataProvider({
  videoTracks: [{ src: localTokenUrl, id: 'local', label: '원본',
    width: 1280, height: 720, duration: durationSeconds, selected: true }],
  textTracks: [],
});
```

`DataProvider`가 로컬 MP4/WebM URL을 원본 SDK의 네이티브 미디어 경로에 넘긴다. `player.src`에 임의 파일 URL을 대입하는 방식과 다르다. 위 트랙 크기는 초기 메타데이터이며 실제 표시 비율은 로드된 영상의 `videoWidth`/`videoHeight` 관측으로 갱신한다. 컨테이너·코덱 지원은 WebView2의 실제 디코더에 의존한다. 원본 SDK를 사용했다는 사실만으로 모든 저장 코덱 지원을 보장하지 않는다.

- SDK의 Vue 런타임 템플릿 컴파일 때문에 필요한 `unsafe-eval`은 이 격리 프레임 응답에만 허용한다. 메인 앱의 `script-src 'self'`에는 추가하지 않는다. 부모와 프레임 모두 별도의 CSP를 적용한다.
- 프레임은 `connect-src 'none'`, `frame-src 'none'`, `worker-src 'none'`, 폼·팝업 제한으로 외부 API·로그·광고·계정 연결을 막는다. SDK 내부 Nelo 로거 자체를 수정하거나 비활성화했다고 주장하지 않는다. 원본 코드의 전송 시도가 있더라도 CSP에서 차단한다. 차단 경고가 개발 콘솔에 남을 수 있다.
- SDK가 요구하는 `localStorage`/`sessionStorage` 인터페이스는 프레임 수명에 한정된 메모리 저장소로 제공한다. 각각 최대 100항목, 키 256자·값 65,536자이며 기존 브라우저 저장소나 계정 정보를 읽지 않는다. 프레임 폐기 시 함께 사라진다.
- 네이티브 정적 프로토콜은 컴파일에 포함된 정확한 파일 목록만 제공하며 임의 경로나 사용자 파일을 해석하지 않는다. `Access-Control-Allow-Origin: *`는 이 공개 정적 코드·스타일의 opaque ESM 로드에만 적용한다. 미디어·채팅 API의 공개 허용이 아니다.
- 저장 영상은 계속 토큰 기반 `atsumi-replay` Range로 읽는다. 원본 `<video>`에 `crossorigin`을 붙이지 않은 실제 WebView2 요청은 `Origin` 없는 Range 요청이었다. 미디어 프로토콜의 `Origin: null`/원격 origin 거부를 완화하지 않는다. 미디어 응답 본문은 최대 1MiB이며 닫힌 토큰은 더 이상 읽을 수 없다.
- 부모↔프레임은 `atsumi-replay-player-v1` 채널, 프레임별 nonce와 실제 `Window` 출처를 검사한다. 부모는 `origin === 'null'`, 프레임은 허용된 부모 origin도 검사한다. 프레임 URL에는 nonce만 있고 녹화 토큰·경로는 없으며, `ready` 후 `init`으로 해당 세션 미디어 URL만 전달한다. 준비가 20초 안에 끝나지 않으면 오류를 표시한다.
- 프라이버시 전환은 소스를 다시 초기화하지 않고 정지·PIP 종료로 연결한다. 뒤늦은 PIP 진입도 프라이버시 상태에서 종료한다. 닫기에는 `dispose`, 미디어 공급자 해제·타이머 정리와 네이티브 세션 토큰 폐기를 사용한다.

### Atsumi 채팅·분석 어댑터와 제한

- 원본 VOD 플레이어·슬롯·테마를 재사용하지만 공식 사이트 전체를 실행하지 않는다. 로컬 저장본에 의미 없는 온라인 클립 만들기·스트리머 샵·라디오 모드는 Atsumi 어댑터가 마운트 시 제거한다. 원본 vendor 바이트는 변경하지 않는다. 로그인·채팅 전송·후원·온라인 추천·계정 설정 동기화는 제공하지 않는다.
- 원본 프레임에는 저장 채팅 본문·프로필·원시 사용자 ID를 보내지 않는다. 기존 `RecordingReplayChat`가 부모 쪽에서 안전한 저장 꾸밈과 공개 프로필 클릭을 처리한다. 시간·탐색 상태만 프레임에서 받아 앞뒤 탐색·보정·오래된 응답 폐기 규칙을 유지한다.

## 배지·이모티콘과 오프라인

채팅 DOM이나 수신한 HTML을 저장하여 실행하지 않는다. 플레이어의 고정 공개 슬롯 템플릿 재사용과 별개로, 채팅은 저장된 닉네임·허용 색상·배지·이모티콘만 안전하게 렌더링한다. 후원 UI·로그인·채팅 전송·모든 공식 효과의 완전 복제는 아니다.

새 채팅 수신 때 허용된 공개 CDN의 꾸밈 이미지를 쿠키 없이 보조 저장한다. 한 작업자, 대기열 128개, 최대 4096파일/128MiB 예산이며 바이트·픽셀·형식·해시를 검사한다. 영상 수신과 별개의 소량 이미지 요청이다. 실패/상한 초과가 녹화·채팅 저장을 막지 않는다.

2026-09-12 추가 변경: 새 녹화 폴더의 `replay-assets`에도 제한된 immutable 사본을 저장한다. `rich.textColor`와 식별 가능한 공개 `profileUrl`, 공식 화면 시청자 수의 `viewer-metrics.jsonl` 관측을 추가했다. 실제 데이터 계약·개인정보·이전 자료 호환·부분 관측 기준은 [채팅 표시와 시청자 관측](CHZZK_CHAT_ENHANCEMENTS.md)을 따른다.

채팅 꾸밈은 재생 중 외부 URL을 요청하지 않고 해당 녹화에서 확인된 로컬 이미지 ID만 허용한다. 누락은 배지명/이모티콘 문자로 대체한다. 과거에 저장하지 않은 이미지나 같은 URL의 사후 변경을 완벽히 복원할 수 없다. 저장 채팅의 HTML/SVG/스크립트는 실행하지 않는다. 공개 프로필은 사용자가 이름을 클릭했을 때만 검증된 주소를 외부 브라우저로 연다.

## 검색·분석 확장 경계

이번 구현은 채팅 밀도 분포와 구간별 고유 참여자 수 기반을 포함한다. 다음 단계는 별도 계약으로 확장한다.

- 본문 검색: 동일 SQLite 인덱스에 버전형 FTS를 추가하고 결과를 현재 `seek`로 연결한다.
- 사용자 검색: 새 기록의 녹화별 salt 기반 `senderKey`를 이용한다. 원시 계정 ID·salt는 저장하지 않고 서로 다른 녹화 사이에서 같은 키라고 가정하지 않는다. 닉네임만 있는 과거 자료의 동일인 판별은 불명확하다.
- 시청자 추이: 새 녹화는 원본 페이지가 사용하는 공개 live-status 메타데이터 API를 10초마다 쿠키·인증 헤더 없이 조회한다(계정/비공개 통계 API나 추가 영상 수신 없음). 같은 channelId/openDate 방송 및 `cvExposure=true`를 검증하고, 숨김·실패·세대 변경은 이전 값을 반복 저장하지 않고 null로 남긴다. 구간별 `viewerCount`는 관측 범위의 시간 가중 평균이며 `viewerSampleCount`/`viewerCoverageSeconds`로 범위를 표시한다. API 샘플은 다음 관측 또는 최대 15 wall초까지만 hold하며 검증된 미디어 시계에만 배속을 환산한다. 기존 2초 DOM 관측 행은 원본 그대로 읽고 6초 한도를 유지한다. 이는 제한된 샘플 유지 가정이며 서버 수치가 10초마다 바뀌거나 공백 없이 관측된다는 보장이 아니다. 과거 미기록 자료는 `not_recorded`/null, 누락 구간도 null이다. 채팅 참여자 수를 시청자 수로 대체하지 않는다.
- 광고·재접속·시계 불연속: 시간 대응 품질을 별도 층으로 보여 채팅 급증과 수집 공백을 구분한다.
- SRT/ASS 내보내기: 선택적 파생 파일로 고려하되 앱의 배지·스크롤 채팅과 동일한 표현을 보장하지 않는다. 영상에 구워 넣거나 원본을 덮어쓰지 않는다.

전체 로그 탐색과 미래 본문/사용자 검색은 다르다. 아직 구현하지 않은 검색이나 서버 측 시청자 통계를 완료된 기능으로 표시하지 않는다.

- 담당자의 실제 브라우저 검증에서 원본 SDK·VOD 슬롯·테마를 함께 로드해 로컬 합성 영상 재생과 원본 설정 창을 확인했다. CSS를 흉내 낸 테스트 컴포넌트가 아니라 실제 공개 번들을 실행한 결과다.

원본 SDK 전환·합성 검증 과정에서 사용자 DB·계정·녹화·채팅 기록을 수정하거나 마이그레이션하지 않았다. 과거 미기록 정보를 만들지 않았으며 커밋·푸시·릴리즈도 하지 않았다.

## 2026-09-12: 원본 채팅 표시 코드 재사용

사용자가 승인한 원본 플레이어 옆 채팅도 실제 공개 CHZZK 렌더 표현식으로 교체했다. `tools/extract_chzzk_chat.mjs`가 해시 고정 원본에서 JQ 채팅 틀·sC 메시지·av 닉네임·f_ 배지·gS 메뉴 아이콘 등을 추출한다. 생성 모듈에는 앱 전체 진입점이나 외부 모듈 import가 없다. 각 표현식 범위·SHA-256·로컬 연결 슬롯은 `src/features/streaming/generated/originalChat.source-manifest.json`에 기록한다.

- 원본 44px 헤더, 14px 메시지, 18px 배지, 24px 이모티콘, 색상 변수·여백·툴팁·역방향 목록을 재사용한다. 제목은 간결한 ‘채팅’이며 원본 메뉴 아이콘에 시간 표시·전체 로그를 연결한다. 기본 시각 표시는 숨김이고 녹화 경과/방송 업타임 선택은 유지한다.
- 채팅 스타일은 하나의 ShadowRoot 안에만 넣는다. 제목 ‘채팅’에 필요한 원본 Sandoll 폰트 조각은 동일 바이트 로컬 파일로 등록하며 기존 `font-src 'self'` 정책을 유지한다. 원본 인증 아이콘도 내부 포함하여 다시보기 중 CDN 조회가 필요하지 않다.
- 저장 로그는 React 문자 노드와 검증된 #RRGGBB 색상, token-local 이미지 주소만 공급한다. 원본 이미지 생성에도 no-referrer를 적용한다. 닉네임 클릭은 기존 token+sequence 기반 공개 프로필 열기만 수행하며 원본 계정·프로필 팝업·구매·후원·채팅 전송 API를 실행하지 않는다. 본문과 닉네임 색상이 다른 저장 기록은 별도 안전한 색상 연결로 보존한다.
- 원본 column-reverse 목록의 음수 scrollTop을 로컬 가상 목록에 맞춘다. 전체 로그는 200개씩 읽고 실제 DOM은 최대 80행이며, 위로 스크롤하면 따라가기 정지, 버튼으로 현재 재생 위치 복귀, 앞뒤 탐색·늦은 응답 폐기 규칙을 유지한다. 폭 변경에 따른 줄바꿈·행 높이도 다시 측정한다.
- ShadowRoot 안의 메뉴·프로필·목록은 플레이어와 같은 탭 이동 순서에 포함한다. 입력 중 단축키를 막고 메뉴 Escape는 메뉴만 닫는다. 기존 플레이어 iframe은 채팅 메뉴·스크롤·크기 조절로 교체하지 않는다.
- 원본 구조 재사용과 모든 온라인 기능 재현은 다르다. 기록에 없는 과거 배지·닉네임 효과·후원 카드를 소급 생성하지 않으며, 저장 이미지가 없거나 손상되면 배지 설명 또는 이모티콘 원문으로 대체한다. 사용자 DB·실제 녹화·채팅 파일을 이 UI 교체 과정에서 수정하지 않는다.

검증: 원본 채팅 및 다시보기 관련 30개, 전체 프런트엔드 99파일/947개 테스트 통과. 합성 영상으로 960×640 및 큰 기본 창에서 원본 여백·메뉴·스크롤·전체 로그·업타임 표시를 확인했고, 메뉴를 여는 동안 영상은 계속 재생됐다. 자산 재생성 검증은 11개 고정 원본을 오프라인으로 비교한다. 실제 계정 로그인이나 장시간 사용자 녹화 검증을 수행했다는 뜻은 아니다.
