# CHZZK 자동 녹화 · 즉시 녹화

## 사용

- CHZZK → **자동 녹화**에서 채널 주소/ID를 등록한다. 최대 32채널이며 목록과 켜짐 상태는 앱 재시작 후 유지된다.
- 앱 실행 중(트레이 포함) 공개 방송 상태를 약 30초마다 확인한다. 이미 방송 중인 채널을 등록해도 시작 대상이다. 앱 종료/PC 절전 중에는 탐색하지 않으며, PC를 깨우거나 자동 실행 설정을 변경하지 않는다.
- 원래 플레이어의 녹화 버튼은 즉시 시작/중지한다. 권한 동의 체크박스나 시작·중지 확인창은 없다. 파일 마무리는 백그라운드에서 진행한다.
- 실제 시작·마무리 때 우측 하단에 짧게 알린다. 라이브에서는 원래 웹 화면 안에 비모달 알림을 표시하여 화면을 숨기거나, 재생을 멈추거나, 입력을 막지 않는다. 다른 탭에서는 앱의 기존 알림을 사용한다.
- **녹화 중지**는 현재 회차를 건너뛴다. 같은 방송을 즉시 자동 재녹화하지 않는다. 다시 켜면 현재 회차도 재시도한다.
- **녹화 준비**는 아직 저장 전이다. **시도 중지**는 준비/재시도를 취소하며, 실제 **녹화 중**과 구분한다. 시작하지 못했다면 채널 아래 **최근 저장 미시작**에서 시각과 이유를 확인한다. 이 기록은 중지·방송 종료·앱 재시작 뒤에도 유지되며, 나중에 재시도가 성공해도 과거 시도에 대한 기록이다.
- **꺼짐/해제**는 자동으로 시작한 녹화를 마무리한다. 별도로 수동 시작한 녹화는 건드리지 않는다. 등록 해제는 저장된 영상·채팅을 삭제하지 않는다.
- 로그인·그리드 연결이 필요한 채널은 라이브에서 미리 연결한다. 기존에 선택한 그리드 자동 연결만 복원한다. 인증·구독·설치 안내를 임의 클릭하지 않는다.

## 실행 구조

- Rust에서 메타데이터 확인과 녹화 제어를 별도 워커로 수행한다. 프런트엔드 탭 전환, 새로고침, 최소화에 의존하지 않는다. 네트워크 요청 실패는 방송 종료로 간주하지 않는다.
- 연속 2번 종료 상태를 확인하면 녹화를 마무리한다. 방송 회차는 `liveId`(없으면 방송 시작 시각)로 구분한다. 회차를 확인할 수 없거나 정보가 오래되면 새 녹화를 시작하지 않는다.
- 이미 같은 방송이 열려 있으면 기존 수신을 재사용한다. 그렇지 않으면 음소거된 녹화 전용 공식 플레이어를 생성한다. 이 전용 창은 부모 창의 클라이언트 영역 밖 `(-2560, 0)`에 고정한 `1280×720` 웹뷰다. 사용자에게는 보이지 않지만 WebView2의 렌더러는 활성 상태로 유지한다. 일반 시청/Mado 창의 배치·포커스·숨김 정책은 변경하지 않는다. 별도 HLS 다운로드나 화면/소리 재녹화는 하지 않고 기존 원본 데이터·채팅·병합 경로를 이용한다.
- 수동 녹화까지 합쳐 최대 4개, 자동 준비 화면도 최대 4개로 제한한다. 초과 채널은 대기한다. 실패한 연결은 60~120초 뒤 재시도한다.
- 배속과 무관하게 수신 원본을 저장한다. 플레이어 수신이 멈추는 상황의 한계는 기존 원본 저장 방식과 동일하다.
- 자동 녹화 **이후** 같은 채널을 다른 시청 화면에서 새로 여는 경우 숨김 수신 화면을 해당 화면으로 옮기는 기능은 아직 없다. 이 경우 별도 시청 수신이 발생할 수 있다. 단일 수신을 공유하려면 시청 화면을 먼저 연 상태에서 자동 녹화를 켠다.

## 데이터와 보호

- 설정은 앱 데이터의 `chzzk-auto-record.json`에 원자적으로 기록한다. 잘못된 설정은 덮어쓰지 않고 자동 시작을 중지한다.
- 수동 중지 회차도 저장한다. 설정 쓰기 실패 시에도 녹화 중지는 실행하고, 현재 프로세스에서는 재시작을 차단하며 저장 실패를 알린다.
- 채널마다 최근 시작 실패 방송의 첫 사유를 같은 설정 파일에 보관한다. 같은 방송의 반복 실패로 기록/알림을 쏟아내지 않으며, 다음 실패 방송이면 교체한다. 별도의 가짜 녹화 파일은 만들지 않는다. 쓰기에 실패해도 현재 화면에는 이유를 유지하고, 디스크 보관 실패를 알리며 중지는 막지 않는다. 기존 version 1 설정은 수정 없이 읽을 수 있다.
- 채널·문서 세대·일회용 시작 토큰·실제 녹화 ID를 확인한다. 사용자가 이어서 시작한 새 녹화를 이전 자동 작업으로 오인하여 중지하지 않는다.
- 앱 종료/업데이트의 기존 작업 관리에 자동 녹화를 포함한다. 종료 시 전체 녹화의 마지막 영상과 채팅을 먼저 마무리한다.
- 웹 페이지에는 파일 경로, 계정 쿠키, 임의 Tauri 명령 권한을 추가로 제공하지 않는다. 녹화에 대한 앱 확인창 제거는 서비스 측 접근 제한을 해제하는 기능이 아니다.

## 검증 범위

임시 데이터로 등록·복원·중지 회차·네트워크 오류·설정 손상/쓰기 실패·새 수동 녹화 보호·시작 실패 사유 보존을 검증한다. UI는 등록·해제·상태 갱신·즉시 중지·프라이버시·늦은 응답 무시·준비/녹화 구분을 검증한다. 자동 재생과 알림은 가짜 영상 입력으로 검증한다. `auto_receiver_probe`는 실제 WebView2와 운영 코드의 배치 함수를 사용하되, 숨겨진 OS 창/임시 프로필/오프라인 DOM만 사용한다. 실제 계정/방송 개시 및 장시간 무인 녹화는 별도 실사용 확인 대상이다.

## 2026-09-15 시작 전 정체 조사

- 양망두의 해당 회차는 중지 시각(02:53:42 KST)에 `id:21104383` 건너뛰기 상태가 저장되어 있었다. 그러나 공유 `streaming/browser/catalog.jsonl`은 0 bytes이고 `D:\Astumi\CHZZK\BrowserCapture`도 비어 있어, 최근 브라우저 녹화가 등록/저장된 증거는 없었다. 중지 버튼에 의한 삭제 흔적이 아니라 **저장 시작 전 실패**로 판단했다. 복구할 영상 데이터는 찾지 못했다.
- 해당 앱 실행 중 공통 로그에서 `waiting_video`, `appendCount=0`, `appendBytes=0`, `sources=[]`가 반복되었다. 당시 로그에는 채널 ID가 없어 각 항목을 양망두에만 귀속할 수는 없다. 수정 후에는 채널 ID·웹뷰 ID와 준비 실패 단계를 같이 남긴다. URL·쿠키·인증 응답은 로그에 추가하지 않는다.
- 자동 수신 창은 생성 후 `hide()`된 상태였다. [Microsoft의 WebView2 IsVisible 문서](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2controller.isvisible)는 숨겨진 웹뷰의 렌더링·백그라운드 작업 제한을 설명한다. 해당 Windows 런타임에서 숨겨진 웹뷰는 `requestAnimationFrame`과 `ResizeObserver` 콜백이 실행되지 않았고, 이런 콜백에서 영상 요소를 준비하는 플레이어가 초기화되지 않는 경로를 재현했다.
- 수정된 운영 배치 함수를 직접 호출한 오프라인 비교(각 3초, 숨긴 부모 창 크기 변경 포함): 기존 숨김은 화면 갱신 **0회**, 크기 감지 **0회**, 영상 요소 미생성. 수정 배치는 화면 갱신 **495회**, 크기 감지 **30회**, 영상 요소 생성, `1280×720` 유지. 타이머로 화면 갱신만 흉내 낸 숨김 대안은 크기 감지 **0회**라 사용하지 않았다. 횟수는 실행 환경에 따라 달라지며, 테스트는 지속 콜백·고정 크기·부모 창 비노출 여부를 검증한다.
- 이 재현은 자동 수신 창의 초기화 결함을 검증한 것이며 실제 양망두 방송의 장시간 녹화 성공을 뜻하지 않는다. 당시 사용자 설정/DB/녹화 파일은 변경하지 않았고, 이전 실패를 성공 기록이나 임의의 녹화본으로 소급 생성하지 않는다.

### 수정 검증

- 자동 녹화 Rust 테스트 14개 통과: 시작 실패 보존, 중지 회차 유지, 재시도 알림 중복 방지, 구형 설정 호환, 디스크 쓰기 실패, 한 주기 안에 끝난 녹화의 오인 방지 포함.
- 브라우저 관련 Rust 범위 201개: 186개 통과/4개 ignored/파일 핸들 기반 정리·삭제 테스트 11개가 제한 실행 환경에서 실패. 해당 저장소 범위 전체를 일반 Windows 실행 환경에서 임시 파일만으로 재검증하여 41개 모두 통과했다. 파일 보존 정책을 완화하거나 테스트를 우회하지 않았다.
- 관련 프런트엔드 8 files/139 tests, 앱 TypeScript 타입 검사, Vite 빌드 통과.
- 실제 WebView2의 오프라인 `auto_receiver_probe` 통과. 운영 배치 함수를 공유하며 실제 방송·사용자 프로필·사용자 녹화 데이터는 사용하지 않았다.
- `cargo build --offline --bin atsumi` 개발 빌드 통과. 실행 파일은 `src-tauri/target/debug/atsumi.exe`, 72,186,880 bytes, 2026-09-15 03:58:31 KST. 바탕화면 `Atsumi.lnk`는 이 워크스페이스의 개발 런처를 가리킨다. 앱은 종료 상태로 두었으며 커밋·푸시·릴리즈는 하지 않았다.
