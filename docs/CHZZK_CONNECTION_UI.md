# CHZZK 연결 설정과 안전한 확인창

2026-09-15 기준. 일반모드와 마도모드는 하나의 연결 폼을 사용한다. 마도는 네 개의 세로 주소 입력을 제공하며, 탭 선택은 초안만 바꾼다. 실제 시청 컨텍스트는 주소 검증과 네이티브 연결 성공 후 변경한다. 녹화 중 방송·모드·계정 전환 제한은 유지한다. 그리드 연결·로그인·설치 설명은 하나의 `?`에 모았고 hover, focus, Escape를 지원한다.

## 최소 로그인 상태

동일한 Atsumi 전용 프로필의 일시적인 숨김 WebView에서 `getUserStatus`의 `content.loggedIn`만 읽어 `signed_in`, `signed_out`, `checking`, `unknown` 중 하나를 반환한다. 방송 연결 전에도 동작하며, 영상·홈페이지 대신 계정 확인용 JSON 주소만 연다. 비밀번호·쿠키·프로필 식별자를 네이티브나 React로 반환하지 않는다. 브라우저가 저장된 세션으로 공식 서비스에 GET 요청하며 별도 계정 API 권한은 추가하지 않았다.

사용한 경로는 `https://comm-api.game.naver.com/nng_main/v1/user/getUserStatus`다. 공개 응답 형태는 [원 저자의 관측 자료](https://gist.github.com/zeroday0619/2d03e11bd9e0a76e39915ade887058d5)를 참고했다. 공식적으로 문서화된 안정 API 계약이나 실제 사용자 로그인 성공을 검증한 것은 아니다. 네트워크·HTTP·스키마·실행 실패는 `unknown`이며, 4초 fetch 취소·6초 스크립트 콜백·창 생성부터 8초 전체 완료 제한을 둔다. 성공·실패·로그인 전환 시 임시 창을 정리한다. 조회 중에는 이전에 확인한 로그인 표시를 유지하지만 실패가 확정되면 `unknown`과 구체적인 재시도 안내를 표시한다.

자동 조회는 30초 동안 결과를 재사용하고 진행 중 요청은 합친다. ‘상태 확인’은 캐시를 우회하고 새로운 결과 또는 명시적인 실패가 올 때까지 기다린다. 일반모드와 마도모드 모두 확인 중 버튼·실패 안내를 표시한다. 채널 변경은 로그인 상태를 초기화하지 않는다. 계정 변경 때만 세대를 증가시켜 이전 요청의 늦은 결과를 폐기한다.

확인된 로그인 상태에서는 로그아웃만, 확인된 로그아웃 상태에서는 로그인만 활성화한다. `unknown`/`checking`은 계정 조작 금지가 아니므로 두 버튼을 사용할 수 있다. 특히 방송 연결 전에도 로그인 창을 열 수 있다. 실제 계정 변경 작업 중에는 별도 `accountBusy` 상태와 UI 요청 상태로 중복 실행을 막는다.

로그인은 Atsumi 전용 프로필의 NAVER 로그인 창을 열고, 이미 열려 있으면 그 창으로 포커스를 옮긴다. 비밀번호 입력은 공식 로그인 페이지에서만 이루어진다. 로그인 창이 닫히거나 로그인 후 CHZZK로 돌아오면 현재 방송·채팅을 새로 고쳐 세션을 반영한다. ID·비밀번호 로그인과 QR 로그인 모두 같은 `chzzk-browser-profile`을 사용하며 정상 종료·앱 재실행 시 이 프로필을 삭제하지 않는다. 유지 기간은 NAVER가 발급한 세션과 로그인 상태 유지 선택에 따른다. 앱이 쿠키를 별도로 추출·재발급하거나 만료를 연장하지 않으며, QR 승인 코드의 유효 시간과 로그인 세션의 유효 시간을 혼동하지 않는다. [NAVER 로그인 상태 유지 안내](https://help.naver.com/service/5640/contents/19013?lang=ko&osType=COMMONOS), [QR 로그인 안내](https://help.naver.com/service/5640/contents/19014?lang=ko&osType=COMMONOS).

로그아웃은 확인창 없이 Atsumi 전용 CHZZK 프로필의 브라우징 데이터를 지운다. 방송 연결 전이나 활성 마도처럼 일반 시청 WebView가 없으면 같은 프로필을 사용하는 숨겨진 `about:blank` 창을 잠시 만든 뒤 정리한다. Chrome·Edge의 프로필, Atsumi 사용자 DB와 녹화 파일은 대상이 아니다. 시간 초과를 성공으로 표시하지 않고 실제 완료 콜백까지 계정 변경과 녹화 시작을 잠근다.

활성 마도에서도 계정을 변경할 수 있다. 로그인 종료 또는 로그아웃 후 기존 영상·채팅 창을 다시 로드하며, 배치·주소·개별 음성 선택을 유지한다. 계정 전환 시 재연결은 발생하지만 일반 시청창이나 다섯 번째 스트림을 추가하지 않는다. 그리드 연결의 기존 마도 제한은 별개로 유지한다.

인증 결과는 UI 관측값일 뿐 녹화·로그아웃 권한이 아니다. 네이티브 main 호출자 검사, 계정/녹화 guard, 세대 검사는 유지한다. 하나의 공유 gate 아래 모든 마도 창의 녹화·시작 준비·승인 처리 상태를 확인한 뒤 계정 변경을 예약한다. 반대로 계정 변경 중에 들어온 녹화 승인도 거부한다. 상태 mutex는 인증 스크립트/UI 호출 전에 해제하며, 완료 callback도 내부 1회 완료 mutex를 해제한 뒤 상태를 갱신한다. 로그인 창·페이지 변경 시 이전 인증 결과는 세대 검사로 폐기한다.

## 영상이 유지되는 확인창

측정된 신뢰 연결창·녹화 확인창을 아래쪽 sheet로 배치한다. 원본 WebView 크기와 controller visibility는 유지하고, 팝업의 실제 사각형과 그림자 여유 8px만 복합 region에서 제외한다. 팝업 아래 전체 폭을 잘라내지 않는다. 상세 동작은 `CHZZK_VIEWING_UI.md`를 따른다.

네이티브는 먼저 빈 region을 검증하고 전체 child 입력을 끈 뒤, 신뢰 main의 포커스를 확인하고 제한된 region을 다시 공개한다. 표시할 수 있는 영상 영역도 마우스·키보드 입력은 비활성이다. viewport 세대가 바뀌거나 region·포커스 검증에 실패하면 전체 child를 숨긴다. 위치 미측정, 다른 메뉴·팝업, privacy/fullscreen 상태에서는 기존 전체 가림을 유지한다.

공식 페이지는 녹화·화면 저장 의도만 제출한다. 실제 승인은 Atsumi 확인 버튼을 누른 경우에만 보내며, 취소 초기 포커스·만료/세대 검사·녹화 상태 guard를 유지한다. 반복 권리 체크박스 대신 짧은 이용 조건 고지를 유지했다. 채팅 저장 도움말은 식별 가능한 공개 프로필 링크와 시청자 수 관측도 저장됨을 설명한다.

## 검증 범위

- 계정 UI 회귀 테스트는 방송 연결 전 로그인, 상태 조회 실패 시 수동 동작, 확인창 없는 로그아웃, 활성 마도 계정 변경과 배치 보존, 녹화·계정 처리 중 차단을 확인한다.
- 네이티브 단위 테스트는 공유 계정 예약과 다른 창의 녹화 보호, 예약 중 늦은 녹화 승인 거부, 완료 콜백 1회 처리 등을 확인한다.
- `chzzk_account_probe`는 실제 프로필과 별개인 임시 WebView2 프로필에서 연결 전 로그아웃·반복 로그아웃·임시 창 정리를 확인하는 Windows 진단이다. NAVER 페이지나 실제 사용자 계정을 열지 않는다.
- 실제 계정의 비밀번호 입력·로그인 성공과 생방송 재연결까지 자동 검증했다고 주장하지 않는다. 사용자 DB·쿠키·녹화는 테스트에 사용하지 않는다.
- `chzzk_auth_status_probe`는 별도의 익명 프로필로 방송 연결 전 실제 계정 조회·연속 수동 조회·임시 창 정리를 확인한다. `--unavailable-profile`은 임시 프로필 경로에 파일을 놓아 생성 실패의 오류 표시·정리를 확인한다. 네트워크/HTTP 실패는 스크립트 테스트로 검증한다. 사용자 계정이나 실제 녹화는 사용하지 않는다.

### 2026-09-15 수정 검증

- 프런트엔드 실제 소스 110개 파일, 1,086개 테스트 통과. `.runtime`의 이전 감사 복사본은 테스트 검색 대상에서 제외했다.
- Rust 전체 타깃: 라이브러리 757개·main 2개·예제 내 테스트 23개 통과, 라이브러리의 명시적 외부 검증 18개 ignored. `cargo fmt --check`와 `cargo clippy --all-targets -- -D warnings` 통과.
- 네이티브 익명 프로필: 방송 연결 전 수동 상태 확인 2회 모두 `signed_out`, 약 550ms/249ms, 남은 임시 창 0개. 접근 불가 임시 프로필 2회는 약 61ms/62ms 후 `unknown`과 오류 안내, 남은 임시 창 0개.
- 실제 사용자 로그인·QR 승인은 자동화하지 않았다. 서버가 발급한 실제 계정의 세션 지속 시간이나 QR 로그인의 영구 유지를 보장하는 검증은 아니다.
