[현재 검증 범위](CHZZK_OFFICIAL_BROWSER.md)를 아래 과거 HLS 검증 수치와 구분한다. 다음 앱 실행부터 공식 보관함의 확정 조각이 있는 종료 기록은 단일 worker가 자동 병합 예약하지만, 이번 검증에서 사용자 파일의 병합·백필을 실행한 것은 아니며 구형 HLS 파일은 대상이 아니다.

## 연결 범위와 제약

CHZZK 공식 Open API의 라이브 목록은 재생 manifest를 제공하지 않는다. 공식 채팅 구독도
OAuth 사용자의 이벤트 권한을 전제로 하므로 일반 시청자가 임의 방송 채팅을 구독하는 API로
취급할 수 없다. 배포 앱에 공용 client secret을 내장하지 않는다.

이번에는 공개 웹 시청 경로를 해석하는 **실험적 CHZZK 어댑터**를 사용한다.
공식 지원 API라는 뜻이 아니며 서비스 변경으로 연결이 중단될 수 있다. 쿠키·계정 정보는
읽거나 저장하지 않는다. 로그인, 성인 인증, 유료 권한, DRM 등이 필요한 콘텐츠는 우회하지 않고
지원하지 않는 이유를 표시한다. 공개 영상이라도 저장·이용 권한은 사용자가 확인해야 한다.
방송 연결은 사용자가 명시적으로 시작한 경우에만 수행하며 앱 시작/모드 진입 시 자동 녹화하지 않는다.

1차 대상은 라이브이며 VOD·클립·예약·다중 채널 동시 녹화·재송출·채팅 전송은 포함하지 않는다.
한 번에 한 방송을 시청·녹화한다. 시청 전용 임시 캐시가 아니라 시작 이후 수신분을 계속 보존한다.
기본 최대 화질은 1080p이며 720p/480p를 고를 수 있다. 재인코딩하지 않는다.
HLS MPEG-TS 및 초기화 조각이 있는 fMP4를 대상으로 하며 암호화, byte-range, 별도 오디오 트랙 등
지원하지 않는 manifest는 오디오를 누락한 채 성공 처리하지 않고 명시적으로 거절한다.

## 화면

- 기존 Atsumi 배너의 모드 메뉴에 CHZZK를 추가한다. 방송 전용 `라이브`와 `녹화 목록` 화면을 둔다.
- 채널 URL 또는 32자리 채널 ID → 방송 확인 → 권한 확인 → `시청·녹화 시작` 순서다.
- 남은 창 공간을 영상·채팅에 배분하고 원본 영상 비율은 `contain`으로 보존한다.
  연결 설정은 접을 수 있으며 `시청 집중`, `채팅 접기`로 영상 공간을 확장한다.
- 수신 상태, 저장 시간·크기·조각 수, 채팅 연결 상태, 재연결/누락을 따로 표시한다.
- 녹화 종료·중단·오류 상태에서도 확정된 저장본을 재생하고 저장 폴더를 열 수 있다.
- 수신한 채팅 전체를 JSONL로 저장한다. 최근 화면은 200개만 유지하며, `전체 기록 보기`에서
  이전/다음 200개를 읽는다. 전체 파일을 메모리로 불러오거나 DOM에 전부 붙이지 않는다.
- 채팅 시간은 `방송 업타임`/`녹화 경과`를 전환한다. 방송 시작 시각이 없는 과거 기록은
  업타임을 추측하지 않고 정보 없음으로 표시한다.
- 녹화 보관함은 최근 최대 200개를 표시한다. 이전 녹화 파일을 자동 삭제하지 않는다.
- 브라우저 개발 화면에서는 실제 녹화를 성공한 것처럼 가장하지 않는다.

## 구조와 계약

`App`이 방송 화면과 좁은 StreamingApi를 연결한다. `src/features/streaming`은 방송 UI만 소유하며
GalleryId, 갤러리 즐겨찾기, 중복 판정, 다운로드 상태를 재사용하지 않는다.
Rust의 `streaming` 모듈은 provider/chat, HLS 해석, 파일 보관, session service, IPC로 분리한다.
CHZZK의 응답 필드와 서명 URL 처리는 provider 내부에 한정한다.

명령: `chzzk_inspect`, `streaming_start`, `streaming_stop`, `streaming_snapshot`,
`streaming_chat_tail`, `streaming_chat_page`, `streaming_open_folder`.
시작은 requestId와 채널별 활성 세션으로 중복 방지한다.
상태 snapshot에는 revision이 있고, 채팅에는 로컬 sequence가 있다. 늦게 도착한 UI 응답은 버린다.
모드 전환으로 DOM을 정리해도 녹화 중지 명령을 보내지 않는다.

영상 상태: starting → recording ↔ reconnecting → stopping → stopped/completed/failed.
다음 실행에서 비정상 종료 흔적은 interrupted로 복원한다. 채팅 상태는 영상과 독립적이다.
네트워크 실패는 제한된 대기 후 재시도하고, 권한/형식 오류는 무한 재시도로 숨기지 않는다.

## 단일 수신과 보존

외부 HLS → Rust 수신기 → 임시 파일 → 확정된 영상 조각 → 로컬 HLS 플레이어.
플레이어는 세션별 불투명 토큰이 있는 로컬 custom protocol만 읽는다. 외부 방송을 두 번째로
여는 웹 플레이어나 iframe을 병행하지 않는다. 재연결로 인한 재시도까지 절대 0회라는 뜻은 아니다.

기본 저장 위치는 현재 다운로드 루트 아래 `CHZZK`이며, 고유 세션 하위 폴더를 사용한다.
기존 앨범 DB migration 없이 별도 방송 인덱스와 파일 journal을 사용한다.
세그먼트 확정 후 journal을 기록하고, 재시작 시 확정한 파일로 재생 목록을 재구성한다.
영상·채팅을 RAM에 무제한 축적하지 않는다. manifest와 개별 조각 응답 크기를 제한하며
저장 공간 부족 시 오류와 보존된 분량을 알린다. 원본 방송 URL의 토큰은 UI/로그/영구 인덱스에 남기지 않는다.

F5와 WebView 재생 오류는 Rust 수신기를 종료하지 않는다. 앱 정상 종료는 녹화 확인 후 수신을 멈추고
현재 파일 처리를 마무리한다. 트레이 이동은 녹화를 유지한다. 업데이트 설치도 녹화 중에는 차단한다.
앱 프로세스 강제 종료 후에는 확정된 분량을 복구하되 마지막 미확정 조각은 손실될 수 있다.
독립 녹화 프로세스, 전원 장애 무손실, 채팅 전체 누락 방지 및 프레임 단위 동기화는 보장하지 않는다.

채팅은 서버 시각(존재하는 경우), 로컬 수신 시각, 세션 상대 수신 시각과 방송 업타임을 보존한다.
CHZZK `openDate`의 시간대 없는 날짜는 KST로 해석하여 세션 metadata journal에 남긴다.
상대 시각은 영상 PTS와 정확히 같은 값이 아니다. 재연결 누락 경고를 기록하고 최근 UI 목록만 제한한다.
채팅 저장 대기열이 가득 차면 수신 측을 대기시키며, 정상 수신한 메시지를 임의로 버리지 않는다.
디스크 오류·연결 중단·접속 전 메시지 및 비정상 종료 직전 미확정 기록까지 무손실이라는 뜻은 아니다.
이력 조회는 역방향 64 KiB 단위 읽기와 줄 경계 byte cursor를 사용한다. 마지막 미완성 줄은 건너뛰고
잘못된 cursor, 비정상적으로 긴 줄, 손상된 확정 기록은 안전한 오류로 처리한다. 읽을 때 파일을 고치지 않는다.
HTML/스크립트로 렌더링하지 않으며 메시지 크기를 제한한다.

## 영상 확장·채팅 꾸밈 및 지연 조사 (2026-09-11)

- 사용자가 보고한 공식 웹 대비 5~15초 이상 지연은 [별도 조사/설계](CHZZK_LATENCY.md)에 정리했다.
  실제 공개 LLHLS 목록과 약 1초 부분 조각/3.051초 part holdback을 확인했다. 이번 변경에서는
  지연 설정·수신기·녹화 저장 보장을 변경하지 않았다. LLHLS의 한 번 수신/재생·저장 공유는 다음 구현 단계다.
- 일반 화면은 남은 높이에 맞춰 영상을 축소하지 않고, 실제 영상 종횡비(정보 전에는16:9)에 맞춰
  너비를 사용한다. 라이브/보관함의 세로 스크롤을 허용한다. 큰 화면에서 영상이 뷰포트보다 높을 수 있다.
- `채팅과 전체화면`은 영상·채팅을 공통 fullscreen 컨테이너에 넣고, 접힌 채팅도 다시 펼친다.
  video 단독 fullscreen 버튼은 숨긴다. Esc와 닫기 버튼으로 복귀하며 녹화를 중단하지 않는다.
- 채팅 안내/시계/기록 버튼을 `채팅 표시 · 기록`에 접어 두고 메시지 공간을 넓혔다. 시간 표시를
  끌 수 있으며, 줄 구분선을 줄이고 글자/줄간격을 조정했다. 이미지 로드·폭 변경 후에도 최근 메시지를
  따라가되 사용자가 과거로 스크롤한 경우에는 위치를 빼앗지 않는다.
- 수신 메시지의 구독/활동/프로필·viewer/후원 순위 배지, 제공된 literal #RRGGBB 닉네임 색상,
  사용된 `{:id:}` 이모티콘을 정규화해 JSONL에 함께 저장한다. 활성 활동 배지만 표시한다.
  설립자·치트키 자격을 URL이나 배지 번호에서 추측하지 않는다. 제공된 배지 이미지/제목만 표시한다.
- 배지8개·이모티콘16종, 메타데이터/URL/텍스트 크기를 제한한다. 기존 기록에 없거나 손상된
  선택 메타데이터는 텍스트를 지우지 않는다. 기존 파일을 소급 수정하거나 예전 꾸밈을 복구하지 않는다.
- 이미지 주소는 ssl.pstatic.net/nng-phinf.pstatic.net의 제한된 HTTPS 주소만 허용하고,
  Rust에서 공개 IP DNS를 고정 검증한 후 읽는다. 쿠키·인증·프록시·리다이렉트 없이 최대5초/1MiB,
 4개 작업,1024px 변/애니메이션 크기 상한을 적용한다. HTML/SVG를 렌더링하거나 CSP를 넓히지 않는다.
  프런트엔드는 검증된 raster data URL만 사용하고 화면 근처 이미지만 요청한다.
- 이미지 캐시는 메모리에만 유지한다(Rust32MiB/256개, UI16MiB/128개). 기록의 이미지 URL은
  보존되지만 캐시에 없는 이미지 재열람에는 CDN 접속이 필요하다. 완전한 오프라인 이미지 아카이브는 아니다.
  닉네임 색상이 palette code만 제공되면 기본색을 사용한다. 채팅 전송·로그인은 여전히 지원하지 않는다.
- 검증: 전체 프런트엔드85파일/640개, Rust library495개+main2개(14 ignored) 통과.
  최신 위치 보존 테스트를 포함한 CHZZK 최종31개 회귀와 app/node typecheck, fmt, Vite 및 개발 빌드도 통과했다.
  로컬 fixture에서2179×820/960×640 배치, 배지·색상·이모티콘, 채팅 포함 전체화면을 확인했다.
  실제 방송을 새로 녹화하거나 실사용 DB를 수정하지 않았으며 장시간 실채팅 꾸밈 표본 검증은 별도다.
