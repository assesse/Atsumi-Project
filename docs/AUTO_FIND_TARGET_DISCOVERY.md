# Auto Find: 작가·그룹 탐색

## 포함과 표시 기준

- 즐겨찾기 `artist`와 `group`을 독립된 OR 조건으로 탐색한다. 같은 이름의 작가와 그룹은 다른 대상이다.
- 작가 즐겨찾기는 그룹과 무관하게 참여 작품을 찾는다. 그룹 즐겨찾기는 작가 정보가 없거나 다른 작가가 참여한 작품도 찾는다. 그룹으로 작가를 추정하거나 작가 즐겨찾기를 자동 생성하지 않는다.
- 합동지의 모든 참여 작가와 그룹, 실제 탐색에서 확인한 그룹 근거를 함께 확인한다. 완전한 참여 작가 목록이 있으면 과거의 잘못된 대표 작가/매치로 보완하지 않는다.
- Auto Find의 `작가·그룹별`은 현재 즐겨찾기에 일치한 각각의 분류에 표시한다. 전체 후보 수, 페이지 용량, 키보드 이동과 다운로드 요청은 gallery ID로 중복 제거한다. 다운로드 탭의 폴더 분류와 실제 저장 경로는 바꾸지 않는다.
- 최초 매치(`matchedFavorite`)는 호환성을 위해 유지하고 모든 실제 발견 근거(`matchedFavorites`)도 별도로 보존한다. 한 조건을 해제해도 다른 즐겨찾기 조건이 남으면 후보를 유지한다.

## 요청과 기록

1. 실행 시 한국어·일본어·중국어·영어 작품번호 목록을 한 번씩 받는다. 이 실행 안에서만 공유하고 다음 실행에서는 새 목록을 받는다.
2. 대상별 artist/group 작품번호 목록과 언어 ID 집합을 교차한다. 대상 목록만 정렬하며 언어별 전체 목록을 대상마다 다시 다운로드·정렬하지 않는다.
3. 다운로드 이력이 있는 항목, 수동 제외, 유효한 중복 제외를 DB에서 일괄 제거한다. 후보 등록 직전에도 다시 검사하여 도중 변경을 존중한다.
4. 기존 후보는 현재 원본 목록에 여전히 속할 때만 가져온다. 동일 실행에서 이미 해석한 앨범은 작가·그룹 간 상세 조회를 반복하지 않고 발견 근거만 추가한다.
5. 필요한 상세정보만 최대 3개씩 병렬 조회한다. 기존 공용 HTTP 요청 간격, 동시 요청 상한, Retry-After와 재시도를 그대로 적용한다. 이미지는 자동탐색의 상세 조회 대상이 아니다.
6. 대상 하나의 모든 조회·저장이 성공하고 결과가 잘리지 않았을 때, 그 대상의 완료 기준점을 즉시 트랜잭션으로 저장한다. 취소·실패 이후 도착한 작업은 이를 바꾸지 않는다. 다른 대상 실패로 먼저 완료한 대상까지 롤백하지 않는다.

## 증분 탐색과 범위 변경

- 최근에 **본** 작품이 아니라 마지막 성공 탐색의 가장 높은 gallery ID를 사용한다. 10,000 ID 폭의 겹침 구간을 재확인하되 이미 저장한 후보 상세정보는 재사용한다.
- 기본값 `가장 최근 소유 작품 이후`(`newer_than_latest_owned`)는 대상별 검증된 소유본의 **최대 gallery ID**가 하한이다. 하한과 같은 ID도 제외하고, 그보다 큰 작품번호만 상세 조회·후보 대상으로 삼는다. 다운로드 시각은 기준이 아니므로 예전 작품을 나중에 내려받아도 하한이 뒤로 움직이지 않는다.
- 작가는 기록된 모든 참여 작가별로, 그룹은 해당 그룹으로 저장된 소유본별로 독립 계산한다. 완료·격리 산출물, 매니페스트 및 페이지 검증 요건은 기존과 같다. 불완전·실패·모든 페이지 제외 항목은 근거가 아니다.
- 검증된 보유본이 없는 대상은 전체 범위를 탐색하고 UI에 이를 명시한다. 기존 수동 옵션 `전체 기록 포함`은 계속 사용할 수 있다.
- 하한이 높아져 범위가 줄면 기존 후보를 필터링하고 증분 탐색을 유지한다. 하한이 낮아지거나 사라지면 새로 열린 과거 구간만 추가 조회한다.
- 10회 증분 또는 마지막 전체 조회 후 30일, 탐색 정책/모드 변경, 기준점 없음은 전체 범위 재확인 사유다. 조회 제한에 걸렸거나 처리 도중인 대상은 완료 기준점을 갱신하지 않는다.
- 대상별 namespace, 이름, 증분 여부, 유효 ID 수, 상세 요청 수, 소요 시간을 로컬 로그에 남긴다.

## 저장 호환성과 한계

- migration 47은 기존 작가 기준점·후보·제외·검색 범위 기록을 보존하며 namespace별 키와 다중 매치 표를 추가한다. 일부 `artist` 컬럼/필드명은 저장·응답 호환성을 위한 레거시 이름이며 그룹에도 namespace와 함께 사용한다.
- migration 48은 기존 `newer_than_oldest_downloaded` 설정을 `newer_than_latest_owned`로 바꾸고 `include_all_history` 선택과 나머지 설정을 보존한다. 빈 DB 최초 생성은 같은 migration 트랜잭션에서 새 기본값을 적용한다. 이전 번호의 migration은 소급 변경하지 않는다.
- 이전 실행의 mode, `oldestOwnedGalleryId`, 근거 policy 1은 과거 기록으로 보존한다. 새 실행의 근거는 `latestOwnedGalleryId`와 policy 2다. 증분 정책도 2로 올려 옛 기준점이 새 탐색 완료 기록으로 재사용되지 않게 한다. 첫 새 실행은 새 하한 이후 범위를 확인한다.
- 기존 후보 snapshot은 다음 명시적 새로고침 전까지 마지막 실행의 결과다. 실행 기준과 현재 설정이 다르면 UI에 다음 실행부터 새 기준이 적용된다고 표시하고 옛 최저 ID를 최신 보유 ID로 바꿔 표시하지 않는다. 새로고침을 시작하면 새 run으로 바뀌고 새 하한 이하의 과거 후보는 이월하지 않는다. 실행 도중 설정이나 소유본이 바뀌어도 시작 시 저장한 기준을 사용하며 다음 실행에서 반영한다.
- 기존 버전에서 중단된 실행의 임시 기준점을 새 완료 기록으로 소급 승격하지 않는다. 새 버전부터 대상별 완료 저장을 적용한다.
- 언어 선택 UI는 후보의 표시 필터다. 자동탐색 자체는 기존처럼 네 언어를 대상으로 한다.
- 그룹을 처음 탐색하면 기존 작가 탐색과 겹치지 않는 과거 작품을 조회하므로 최초 실행은 여전히 시간이 걸릴 수 있다. 실제 속도 배수는 네트워크 측정 없이 보장하지 않는다.
- 개발 앱의 다음 실행에 DB 업그레이드가 적용된다. schema 48 적용 후 예전 schema 47 이하 바이너리로 같은 DB를 열지 않는다. 앱의 사전 마이그레이션 백업과 기존 릴리즈를 혼동하지 않도록 안내한다.
