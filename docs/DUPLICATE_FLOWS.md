# Atsumi 중복 판별 흐름

2026-09-09 현재 working tree 기준. 자동 판정 규칙은 `balanced_overlap_v5`이며 공개 릴리즈의 동작과 다를 수 있습니다.

## 1. 기능 구분

| 진입점 | 비교 대상 | 결과 및 처리 |
| --- | --- | --- |
| 다운로드 완료 직전 | 신규 B ↔ 같은 작가의 검증된 완료본·다른 검토 대기본 | 중복 후보가 없으면 완료. 있으면 검토 대기. 설정에 따라 수동 또는 자동 처리 |
| 같은 작가 작품 중복 검사 | 보관함의 같은 작가 앨범끼리 | 후보 저장 후 수동 판정. 다운로드 자동 정리 설정과 별개 |
| 두 앨범 직접 대조 | 선택 또는 ID 입력한 완료본 두 개 | 작가 조건 없이 직접 비교. 수동 판정 |
| 합본 포함 후보 일괄 처리 | 한 보존본과 직접 완전 포함관계가 검증된 여러 앨범 | 사용자가 체크한 항목을 하나씩 재검증·제외 |
| 판본 페이지 병합 | A/B의 대응 페이지 | Ctrl+클릭으로 선택한 페이지를 교체. 성공 후 제공 앨범 제외 |
| 선택 앨범 내부 페이지 검사 | 각 앨범 안의 페이지끼리 | 중복 페이지 그룹 제시. 사용자가 계획 확인 후 격리 |
| 다운로드 이력·탐색 제외 필터 | 갤러리 ID | 이미지 비교가 아닌 재등장·재요청 방지 |

## 2. 공통 이미지 비교

- 저장 파일(정규화된 WebP 바이트)의 SHA-256이 같으면 정확 일치. 그렇지 않으면 이미지 해시·윤곽·정보량을 비교합니다.
- 일반 시각 비교는 detail 거리 ≤260, 중앙 detail ≤48, pHash ≤16, coarse dHash ≤20, 경계 유사도 ≥0.62, 내용 유사도 ≥0.60, 종합 시각 점수 ≥0.80을 요구합니다. 저정보 페이지는 일반 시각 비교에서 제외합니다.
- 순서를 유지하는 일대일 페이지 대응을 구합니다. 중간에 추가·누락된 페이지는 허용합니다.
- 동일 SHA와 해시 프로필의 저장된 분석값을 재사용합니다.
- ‘포함률’은 **대응 페이지 수 ÷ 해당 앨범 페이지 수**입니다. 픽셀 유사도와 다릅니다.
- ‘신뢰도’는 가중 합성 점수이며 실제 오탐 확률을 뜻하지 않습니다.
- ‘번역·가공 판본’은 시각 유사성 분류입니다. OCR로 번역 내용을 확인하지 않습니다.

공유 분석기의 분류 순서:

| 관계 | 조건 |
| --- | --- |
| 정확 일치 | 양쪽 모든 페이지가 SHA 일치 |
| 번역·가공 | 2쌍 이상, 양쪽 포함률 ≥65%, 정확 SHA 일치가 대응의 절반 미만, 평균 시각 점수 ≥0.80 |
| 포함 | 2쌍 이상, 어느 한쪽 포함률 ≥99.9% |
| 부분 겹침 | 2쌍 이상, 양쪽 포함률 ≥45%, 평균 시각 점수 ≥0.80 또는 정확 일치가 절반 이상 |

조건이 겹치면 위쪽 관계가 먼저 적용됩니다. 따라서 시각적으로 전부 포함되어도 ‘번역·가공’으로 분류될 수 있습니다. 다운로드 경로에서는 양쪽 포함률 ≥95%이면 다시 ‘거의 동일’로 분류합니다. 작가·그룹·제목·페이지 수·정확 일치 앵커 등 추가 조건을 만족하는 판본에 한해 식자 변경 보조 비교도 수행합니다.

근거: `src-tauri/src/application/duplicate_analyzer.rs`의 `classify_alignment`, `should_try_typesetting_fallback`, 페이지 매칭 함수.

## 3. 다운로드 중복 검사

`모든 페이지 저장 → 저장 파일 SHA 검증 → 중복 검사 → 최종 manifest 작성·검증 → 완료`

중복 검토는 manifest 최종 생성 전이므로 진행률 100%여도 완료가 아닐 수 있습니다.

### 대상

- 작가 키를 NFKC·소문자·밑줄/공백 정리 후 비교합니다. 공통 작가가 없으면 비교하지 않으며 신규 앨범의 작가 정보가 없으면 gate를 건너뜁니다.
- 완료본 외에 다른 중복 검토에서 대기 중인, 전 페이지가 검증된 다운로드도 비교합니다.
- 제외·미검증·누락·진행 중 병합 자료는 비교 대상에서 거릅니다.
- 과거 ‘둘 다 보존/오탐’은 파일 지문과 분석 프로필·정책이 같으면 다시 묻지 않습니다. 내용이나 정책이 바뀌면 다시 비교할 수 있습니다.

### 검토를 띄우는 추가 기준

아래 조건은 공유 분석기의 관계 분류를 통과한 뒤 적용됩니다. 자동 정리 기준이 아닙니다.

| 다운로드 검토 관계 | 추가 조건 |
| --- | --- |
| 거의 동일 | 전체 정확 일치 또는 양쪽 포함률 ≥95%. 작은 쪽이 3장 이하면 그쪽 전체 SHA 일치 필요 |
| 포함 | 작은 쪽이 4장 이상이면 매치 ≥4·한쪽 포함률 ≥90%. 더 짧으면 작은 쪽 전체 SHA 일치 필요. 선행 포함 분류의 ≥99.9% 조건도 충족해야 함 |
| 번역·가공 | 작은 쪽 >3장·정보 있는 매치가 과반. 매치 ≥6·한쪽 ≥90%, 또는 작은 쪽 ≥8장·매치 ≥8·양쪽 ≥75%·연속 일치 ≥8 |
| 부분 겹침 | 작은 쪽 >3장·정보 있는 매치가 과반. 매치 ≥6·한쪽 ≥80%, 또는 매치 ≥10·양쪽 ≥60% |

유효 후보의 파일·해시 확인에 실패하면 검사를 건너뛰어 완료시키지 않고 재시도 가능한 오류로 멈춥니다. 이미 다른 판정에서 제거된 후보는 재확인 후 제외합니다. 비교 근거가 바뀌면 이전 검토를 `stale`로 전환하고 다시 검사합니다.

근거: `download_overlap.rs`의 `analyze_download_overlap_pair`, `download_supervisor.rs`의 `run_overlap_review_gate`.

## 4. 자동 정리 배너와 실제 자동 실행

### 배너 표시 조건

1. 설정이 ‘추천만 표시’ 또는 ‘안전 기준 자동 정리’입니다.
2. 검토 상태가 `pending`이고 미처리 후보가 있습니다.
3. 아래 자동 판정 조건을 만족하는 후보가 하나 이상 있습니다.

배너는 **현재 선택한 A/B 탭이 아니라 검토 묶음 전체**를 봅니다. 다른 후보가 조건을 충족해서 보일 수도 있습니다. 완료본 수동 대조 화면은 자동 모드를 전달하지 않아 이 배너가 표시되지 않습니다.

### 판정 기준

| 조건 | 완전 포함 경로 | 일반 경로 |
| --- | --- | --- |
| 관계 | 더 큰 판본이 다른 판본을 포함 | 포함 또는 거의 동일 |
| 제거할 쪽 포함률 | 100% | ≥95% |
| 제거할 쪽 고유 페이지 | 0 | 위 포함률을 충족하는 범위 |
| 양쪽 페이지 수 차이 | 제한 없음 | ≤5장 |
| 최소 매치 | `min(4, 작은 쪽 전체 장수)` | 동일 |
| 신뢰도 | ≥85% | ≥90% |
| 연속 일치 | `min(2, 매치 수)` 이상 | 최장 연속 일치 ÷ 전체 매치 ≥75% |
| 정보 있는 매치 비율 | ≥75% | ≥75% |
| 페이지 대응 | 작은 쪽 모든 페이지 대응·고유 페이지 0·양쪽 번호가 엄격히 증가 | 저장된 대응·연속 일치 근거 사용 |
| 3장 이하 작품 | 매치 전부 SHA 일치 | 동일 |

‘부분 겹침’과 ‘번역·가공’ 관계는 자동 정리하지 않습니다. 저장된 비교 증거가 부족해도 수동 검토로 남습니다. 후보당 페이지 대응 저장 한도는 2,000개입니다.

보존 우선순위:

- 포함관계: 포함하는 판본을 보존합니다. 무검열 표식보다 우선합니다.
- 거의 동일: 제목 표식(무검열 > 미표시 > 검열) → 페이지 많은 쪽 → 동률이면 기존 A.
- 표식은 제목의 `uncensored`, `decensored`, `uncen`, `無修正`, `无修正`, `無碼`, `无码` 등을 읽습니다. 이미지의 실제 검열 상태를 분석하지 않습니다.
- 여러 후보 중 기존 A를 남겨야 하는 직접 비교가 하나라도 있으면 신규 B를 제외하고 기존 후보들은 유지합니다.
- 그렇지 않으면 B가 안전하게 대체하는 기존 후보만 제외하고 나머지는 직접 검토로 남깁니다. 공통 앨범과 닮았다는 이유만으로 다른 두 앨범의 중복을 추론하지 않습니다.

### 실행 조건과 제한

- ‘추천만 표시’: 안내만 표시하며 직접 선택해야 적용됩니다.
- ‘안전 기준 자동 정리’: 검토 창이 닫히고 다른 판정 작업이 없을 때 프런트에서 자동 요청을 보냅니다. 로드된 목록의 검토 항목이 대상입니다.
- 따라서 **‘검토 미루기’로 닫아도 자동 모드에서는 정리될 수 있습니다.** 멈추려면 설정을 ‘추천만 표시’나 ‘사용 안 함’으로 바꿔야 합니다.
- 서버는 적용 전에 review revision·파일 지문·보존 대상·규칙과 비교 근거를 재검증합니다. 자동 모드 설정 자체의 실행 차단은 프런트가 담당합니다.
- UTC 하루 자동 결정 최대 10건입니다. 한국시간 오전 9시에 날짜가 바뀌며, 앨범/검토창 개수가 아니라 개별 결정 횟수입니다.
- 같은 검토 ID·revision은 실행 세션 중 중복 자동 시도하지 않습니다. 제한·오류가 나면 해당 자동 처리 순회를 중단하며 이미 성공한 결정은 유지됩니다.
- 배너는 하루 한도·파일 재검증 결과까지 확인한 표시가 아닙니다. 배너가 보여도 실제 적용은 중단될 수 있습니다.
- 현재는 고정 규칙입니다. 저장된 수동 판정을 자동 학습해 임계값을 바꾸지는 않습니다.

근거: `src/state/downloadOverlapAuto.ts`, `src/App.tsx`의 자동 판정 effect, `download_supervisor.rs`의 자동 정책 검증, `sqlite_repository.rs`의 `overlap_decision_apply`.

## 5. 수동 판정·일괄 처리·병합

### A/B 버튼

| 선택 | 결과 |
| --- | --- |
| 기존 A 제거 | 선택한 A만 제외. 신규 B의 다른 후보가 남으면 계속 검토, 없으면 다시 완료 절차 진행 |
| 신규 B 제거 | B 취소·제외. 기존 A와 다른 기존 후보는 유지 |
| 둘 다 보존 | 두 판본 유지·해당 지문 쌍의 예외 저장 |
| 오탐 판정 | 두 판본 유지·오탐 라벨 및 예외 저장 |
| 검토 미루기 | 창 닫기. 자동 모드라면 닫은 뒤 자동 처리 가능 |

일반 수동 판정은 자동 임계값을 강제하지 않지만 파일·revision 재검증은 유지합니다. 이미 제외·격리한 앨범을 ‘둘 다 보존’ 버튼으로 복구하지는 않습니다.

### 합본 포함 후보 일괄 처리

- 하나의 보존 합본과 직접 완전 포함관계인 후보만 묶습니다. 다른 검토에서 방향이 반대로 저장된 관계도 포함합니다.
- 체크된 항목을 하나씩 최신 상태로 다시 불러와 적용합니다. 이 버튼은 수동 선택이지만 완전 포함 증거를 서버가 다시 검증합니다.
- 중간 오류가 나면 이후 항목은 멈추고 앞서 성공한 항목은 유지합니다. 불확실한 관계는 별도 검토로 남습니다.

### 완료본 검사·직접 대조

- 같은 작가 전체 검사는 같은 작가 키가 있는 자료끼리, 직접 대조는 지정한 완료본 두 개를 작가 조건 없이 비교합니다.
- 새 후보를 저장할 뿐 자동 제외하지 않습니다. 수동 A/B 판정을 적용해도 보존본을 재다운로드하지 않습니다.
- A/B 방향은 입력 순서가 아니라 저장된 parent/candidate 방향입니다.
- 과거 판정 예외 때문에 다시 검사해도 새 후보가 없을 수 있습니다.

### 페이지 병합

- 대응 페이지를 Ctrl+클릭해 한쪽에서 최대 200장 선택합니다. 선택한 제공 페이지가 반대편 대응 위치를 교체하며 대상의 추가 페이지는 유지합니다.
- 현재 UI는 성공 후 제공 앨범 전체를 제외합니다. 따라서 제공 앨범의 모든 페이지가 반대편에 유일하게 대응해야 합니다. 제공본에만 있는 페이지가 있으면 진행하지 않습니다.
- 양쪽 저장 파일 SHA·manifest 검증 → staging 복사·교체 → manifest 갱신 → 파일 재확인 → 기존 대상 백업 → 교체·DB 확정 순서입니다.
- 변경된 페이지의 해시·검토·미리보기를 갱신합니다. 중간 실패·앱 종료는 복구 기록으로 처리합니다.
- 백업은 `.atsumi-page-merges/<merge-id>/original`에 남지만, 성공한 병합의 원클릭 실행 취소 UI는 없습니다.

근거: `src/state/downloadOverlapContainment.ts`, `duplicate_supervisor.rs`, `completed_pair.rs`, `overlap_merge.rs`, `src/App.tsx`의 수동 적용 함수.

## 6. 앨범 내부 페이지 검사

- Downloads의 선택 완료 앨범에 대해 수동 실행합니다. 전체 내부 검사는 유지보수 재구축에서 실행할 수 있습니다.
- 원본 장수가 500 이상이면 건너뜁니다. 이미 제외한 페이지를 빼서 이 제한을 우회하지 않습니다.
- 동일 SHA는 단독·저정보 페이지라도 정확 중복으로 검출할 수 있습니다. 비정확 시각 중복은 정보량과 연속 블록 증거를 함께 확인합니다.
- 기본 보존 추천은 가장 이른 원본 페이지이며 최고 화질 자동 선택은 아닙니다.
- 검사 자체는 파일을 옮기지 않습니다. 유지/격리 선택 → 계획 확인 → 적용해야 이동합니다.
- 계획은 15분 만료 및 revision 재검증을 사용합니다. 페이지는 앨범 내부 `.atsumi-page-quarantine/<plan-id>/`로 이동하고 undo로 복원할 수 있습니다.

근거: `internal_duplicate_analyzer.rs`, `internal_duplicate_supervisor.rs`, `internal_duplicate_repository.rs`.

## 7. 제외·격리·복원과 ID 필터

| 처리 | 파일 위치·상태 | 복원 |
| --- | --- | --- |
| 다운로드 검토에서 완료된 기존 A 제거 | `.atsumi-quarantine` · quarantined | 별도 격리 복원. 탐색 hidden 해제는 별개 |
| 신규 B·대기 staging 제외, 완료본 수동 A/B 제외 | `.atsumi-excluded` · 취소/숨김 | 설정의 제외 복원은 폴더 복원 후 숨김 해제. 자동 재다운로드·완료 처리 아님 |
| 내부 중복 페이지 격리 | 앨범 내부 `.atsumi-page-quarantine` | 페이지 격리 undo |

어느 경로도 영구 삭제하지 않습니다. 복원 위치에 다른 파일·폴더가 있으면 덮어쓰지 않습니다. **탐색 제외 해제, 격리 파일 복원, 완료 상태 복원은 같은 동작이 아닙니다.**

- 일반 다운로드 UI는 이미 다운로드 정보가 있는 ID를 새 항목으로 추가하지 않습니다. backend queue는 활성 동일 ID 재사용·requestId 멱등성을 보장하지만 완료 ID를 모든 API에서 일괄 차단하는 것은 아닙니다.
- 중복 제외 ID는 명시적 복원 전 일반 재시도를 차단합니다.
- Auto Find는 수동 제외·중복 숨김 외에 다운로드 이력이 하나라도 있는 ID를 제외합니다. 실패·취소 이력도 포함합니다. 숨김만 복원해도 다운로드 이력 필터는 남습니다.
- Explore의 제자리 블라인드와 다운로드/Auto Find의 숨김은 이 ID 정책에 따른 표시입니다. 새 이미지 중복 검사가 아닙니다.

근거: `excluded_artifacts.rs`, `sqlite_repository.rs`, `src/App.tsx`의 복원·다운로드 추가 함수.

## 8. 확인한 표시·구조 문제

이번 변경은 안내 문구·호버 설명만 조정했으며 아래 판정 로직은 변경하지 않았습니다.

1. 설정 호버에 남아 있던 과거 ‘98%·1.5배·8장’ 설명은 현재 v5 기준으로 수정했습니다. 검토 배너와 같은 설명을 사용합니다.
2. 완료본 오탐 판정은 backend에 구별 저장되지만 `completedPairReview.ts`가 구형 `exclude_pair`를 ‘둘 다 보존’으로 변환하여 재열기 때 라벨이 구별되지 않을 수 있습니다. 미수정.
3. 같은 작가 전체 스캔은 숨김·이동 완료 제외 자료를 입력 단계에서 모두 거르지 않아 불필요한 해시·비교가 발생할 수 있습니다. 후보 저장 시에는 숨김을 차단합니다. 직접 두 앨범 대조의 대상 필터는 더 엄격합니다. 미수정.
