# 개인 즐겨찾기와 컬렉션

Hitomi를 열람하면서 앨범이나 특정 페이지를 한 번 눌러 저장하고, 나중에 같은 작품과 장면으로 돌아오는 기능이다. 관심 작가·태그, Auto Find, 앨범커버, 공개 후기와는 별개이며 자동 다운로드나 공개 전송을 하지 않는다.

## 저장하는 순간

앨범 카드와 플로팅 디테일에서 앨범을 저장한다. PAGE PREVIEW에서는 현재 페이지를 저장한다. 두 쪽 보기에서는 각 페이지를 구분한다. 저장해도 화면이나 현재 페이지는 바뀌지 않는다. 앨범과 페이지 저장은 독립이며 한 앨범의 여러 페이지를 저장할 수 있다.

첫 클릭은 미분류 즐겨찾기에 즉시 저장한다. 컬렉션 지정은 선택 사항이다. 컬렉션 메뉴에서 새 이름을 만들거나 여러 기존 컬렉션을 선택한다. 저장 실패를 성공처럼 표시하지 않으며 중복 클릭을 막고 재시도할 수 있게 한다.

## 다시 찾는 순간

Hitomi 좌측 메뉴의 내 즐겨찾기에서 앨범과 페이지를 구분한다. 최근 등록순으로 표시하고 제목·작가·작품번호 검색, 전체·미분류·컬렉션 필터를 제공한다. 목록을 일부씩 불러오며 이미지 로더와 설정의 미리보기 크기를 재사용한다. 앨범은 상세보기로, 페이지는 기존 PAGE PREVIEW의 해당 페이지로 돌아간다. 열람 후 목록의 필터와 위치를 유지한다.

## 정리하는 순간

컬렉션 이름 변경과 삭제를 지원한다. 컬렉션 삭제는 연결만 제거하며 즐겨찾기와 원본은 유지한다. 즐겨찾기 해제는 해당 항목과 컬렉션 연결만 제거한다. 다른 앨범·페이지와 다운로드 파일에는 영향을 주지 않는다.

## 데이터와 안전

개인 기록은 앱 데이터 폴더의 personal-library.sqlite3에 별도 저장한다. 기존 다운로드 DB의 스키마를 바꾸지 않고 기존 탐색·캐시·설정 초기화와 분리한다. 앱 제거 시 데이터 폴더 자체를 지우면 이 기록도 없어지므로 원본 백업이나 외부 동기화를 의미하지 않는다. 이번 범위는 Hitomi이며 source를 키에 포함해 이후 다른 소스를 추가할 수 있게 한다.

항목은 source, galleryId, 원본 페이지 번호로 식별하며 앨범은 page 0을 사용한다. 제목·작가·총 페이지 수를 저장해 원본이 없어도 목록은 남긴다. 로컬 페이지의 기존 SHA256을 얻을 수 있으면 함께 저장하되 새 이미지 분석이나 전체 해시 검사는 하지 않는다. 목록 조회 및 열기 직전에는 기존 DB를 읽기 전용으로 확인한다. 제외·격리·교체·병합 중·확인 실패 상태는 안내하고 자동 복원하지 않는다. 원격 작품 삭제나 파일의 외부 변경은 기존 이미지 로더에서 최종 확인한다.

개인 기록 DB의 변경은 짧은 트랜잭션으로 처리한다. 네트워크와 이미지 로딩을 DB 트랜잭션이나 UI 스레드 안에서 수행하지 않는다. 컬렉션과 항목의 다대다 연결, 재시작 후 보존, 원본 DB 불변, 페이지 변경·제외, 실패와 키보드 동작을 회귀 테스트한다.
