# Atsumi Ink — 디자인 시스템 1차 명세

상태: 검토용 v0.1 · 작성일: 2026-09-23 · 대상: Atsumi 데스크톱 앱

> 콘텐츠를 크게 보고, 탐색은 이어가며, 필요한 조작과 상태만 명확하게 보여준다.

## 0. 이 문서의 성격

사용자의 실제 요구와 반복된 수정 이력을 공통 규칙으로 정리한 문서다. 명세 작성 자체가 새로운 테마나 기능 변경의 승인을 뜻하지 않는다. 최초 작성에서는 문서만 정리했으며, 이후 사용자가 요청한 적용 범위는 [결정 이력](DECISION_HISTORY.md)의 E26·E27에 별도로 기록한다.

근거는 현재 `Atsumi UI/UX` 대화, 추가로 조회한 프로젝트 대화 4개에서 반환된 53개 턴, 현재 작업 트리의 관련 코드·문서다. 모든 보관 대화를 전수 조사한 것은 아니다. 조회한 턴에도 계승된 이력이 있으므로 53개가 독립된 요구 53개를 뜻하지 않는다. 기준 HEAD는 `82eeda3`이며 미커밋 변경을 포함해 읽었다. 실행 앱·배포본과 같다고 보장하지 않는다.

### 근거 표기

- **[요구]** 사용자가 직접 요청하거나 명시적으로 선택한 방향.
- **[현행]** 이번에 읽은 소스·문서에 존재하는 동작/값. 사용자가 정확한 수치까지 승인했다는 뜻은 아니다.
- **[제안]** 여러 사례에서 일반화한 v0.1 규칙 또는 새 설계값. 적용 전 검토 대상.
- **[후순위]** 사용자 요청은 있지만 이번 1차 적용 범위 밖인 항목.

`E01` 등의 번호는 [결정 이력](DECISION_HISTORY.md)의 상황·요구·설명·후속 변경을 가리킨다. 과거 응답에 없는 판단 이유는 당시 사실로 단정하지 않고 이번 해석으로 구분했다.

### 적용 우선순위

최신 명시적 사용자 결정 → 해당 기능의 최신 검증된 계약 → 이 문서의 공통 원칙 → 시각 제안 순서로 판단한다. 데이터 보존·권한·플랫폼 제약은 장식 통일을 이유로 제거하지 않는다. 과거 작업에서 허용한 재시작·삭제·푸시를 상시 권한으로 재사용하지 않는다.

## 1. 제품의 성격과 목표

Atsumi는 Hitomi 앨범, Danbooru post, CHZZK 방송·녹화본을 다루는 콘텐츠 탐색·보관 도구다. 쇼핑 앱이나 홍보 사이트처럼 큰 설명 영역과 CTA를 반복하는 구성이 맞지 않는다. [현행: README, workspaceRegistry]

**[제안] 제품 성격:** 조용한 화면, 높은 탐색 밀도, 선명한 상태, 필요한 순간의 풍부한 미리보기.

### P1. 콘텐츠 우선 — E02, E03, E09

- [요구] 미리보기 크기를 희생해 카드 개수만 늘리지 않는다. 정보·장식의 면적부터 줄인다.
- [요구] 상세형과 요약형을 제공하며, 요약형의 즐겨찾기 태그는 공간이 허용될 때만 보인다.
- [요구] 확대 이미지가 작화·판본 차이를 판단할 만큼 유용해야 한다. 저해상도 확대를 고화질이라고 표시하지 않는다.

### P2. 탐색 연속성 — E01, E05, E10, E16

- [요구] 새 작가 탐색, 관련 작품 열기, 플랫폼 전환이 원래 검색·페이지·스크롤을 파괴하지 않는다.
- [제안] 화면을 바꾸는 행위와 백그라운드 작업을 시작·중지하는 행위를 분리한다.
- [요구] 저장되는 보기 설정은 다음 실행에도 복원한다. 단, 세션 RAM 캐시까지 재실행 후 복원된다고 안내하지 않는다.

### P3. 간결하되 중요한 사실은 숨기지 않기 — E04, E13, E19

- [요구] 설정의 기본 설명은 가능하면 한 줄, 최대 두 줄. 추가 정보는 도움말로 분리한다.
- [제안] 데이터 삭제·파일 미복원·부분 실패처럼 결정에 필수적인 결과는 호버에만 숨기지 않는다.
- [제안] 처리 결과와 다음 행동을 먼저 쓰고 내부 단계·오류 코드는 상세에 둔다.

### P4. 직접 조작과 일관된 반응 — E05, E06, E15, E17

- [요구] 시청 시작·종료, 스크린샷 등 반복 작업에 불필요한 확인창을 끼우지 않는다.
- [요구] 키보드와 마우스로 같은 작업을 할 수 있다. 세부 UI를 한 번 클릭해야만 단축키가 살아나는 구조를 피한다.
- [제안] 포커스 이동, 성공 알림, 로딩 표시도 컴포넌트 계약에 포함한다.

### P5. 현재 상태와 기록을 분리 — E11, E12, E19

- [요구] 현재 녹화 성공 뒤에 과거 실패를 현재 오류처럼 남기지 않는다.
- [요구] 이미 중복 처리한 앨범을 일반 다운로드 실패처럼 보여주지 않는다.
- [제안] 전송 완료, 해시/검증 중, 판본 검토 대기, 사용 가능한 완료를 서로 구별한다.

### P6. 속도와 안전을 함께 설계 — E07, E08, E18, E20

- [요구] 목록·요약을 먼저 표시하고 무거운 작업은 뒤에서 진행한다. 화면만 그려지고 버튼이 안 눌리면 준비 완료가 아니다.
- [요구] 이미 준비된 썸네일·태그·대표 미리보기를 재사용한다.
- [제안] 실제 화면의 요청을 우선하고 예열은 제한된 대기열로 수행한다. 서버 대기 지시·원본 검증·메모리 한계를 무시해 속도를 높이지 않는다.
- [제안] 성능은 체감 주장 대신 시작 시간, 화면 응답, 재사용 여부, 디코딩 메모리, 디스크 읽기로 확인한다.

## 3. 기초 스타일

### 3.1 색상과 테마 — E02, E14

[요구] 로고의 검은 톤을 기반으로 한다. [현행] `src/atsumi-ink.css`가 아래 값을 정의한다. 정확한 HEX 값은 기존 구현의 기준점이며 사용자 직접 지정값은 아니다.

| 의미 | 현행 토큰 | 현재 값 | 사용 규칙 |
| --- | --- | --- | --- |
| 앱 바깥 바탕 | `--canvas` | `#100f13` | 기본 캔버스 |
| 사이드 레일 | `--rail` | `#151319` | 지속 탐색 영역 |
| 작업 바탕 | `--workspace` | `#17151b` | 콘텐츠 뒤의 저강도 배경 |
| 카드 표면 | `--surface` | `#211e26` | 카드·기본 패널 |
| 떠 있는 표면 | `--surface-raised` | `#2b2831` | 팝업·메뉴 |
| 기본 글자 | `--text` | `#f2eff3` | 제목·본문 |
| 보조 글자 | `--muted` | `#aaa4ae` | 부가 정보. 필수 상태를 지나치게 흐리게 하지 않음 |
| 선택·포커스 | `--primary` | `#d97a8d` | 로즈. 화면 전체를 채우는 장식색으로 남용하지 않음 |
| 소스·정보 | `--source-teal` | `#63b7b4` | 보조 정보/소스 식별 |
| 즐겨찾기 | `--favorite` | `#e6aa58` | 별표·채널 배너 강조 |
| 성공 | `--success` | `#67c59b` | 완료·문제 없음 |
| 주의 | `--warning` | `#e6aa58` | 검토 필요. 즐겨찾기와 다른 아이콘·문구를 사용 |
| 위험·실패 | `--danger` | `#f08386` | 실패·파괴적 동작 |

- [제안] 각 화면에서 HEX를 새로 복제하지 않고 의미 토큰을 사용한다.
- [제안] 같은 주황색을 쓰더라도 별표와 경고 삼각형을 구별한다. 로즈 선택 상태와 여성 태그도 색만으로 구별하지 않는다.
- [제안] 어두운 표면끼리는 테두리·위치·그림자로 층을 구분한다. 모든 카드에 빛나는 테두리나 큰 그림자를 넣지 않는다.
- [후순위] 밝은/다크/시스템 테마 선택. 시스템 모드는 OS 테마 변경에도 따라간다. 현행 `color-scheme: dark`만으로 시스템 연동이 구현된 것으로 보지 않는다. 밝은 팔레트는 이번에 확정하지 않는다.

### 3.2 글자와 정보 밀도 — E03, E04

[현행] 기본 글꼴은 Segoe UI Variable 계열 → Segoe UI → Malgun Gothic → sans-serif다. 카드에는 `shared/gallery-preview-presets.json`의 크기 연동 규칙이 있다.

| --- | --- | --- | --- |
| 160px | 14px | 11px | 2 |
| 190px | 15px | 11.5px | 2 |
| 220px | 16px | 12px | 3 |
| 250px | 17px | 12.5px | 4 |
| 280px | 18px | 13px | 5 |

이 값은 Hitomi 카드 프리셋이다. 요약 보기 모드의 `compact`와 폭 프리셋 이름 `compact`를 같은 설정으로 혼동하지 않는다. Danbooru나 채널 배너에 이 표를 일괄 강제하지 않는다.

- [제안] 설정 본문은 14~15px를 시작점으로 검증한다. 보조 글자 크기를 줄이는 것보다 설명을 줄이는 것을 우선한다.
- [제안] 작품명은 카드에서 최대 두 줄을 기본으로 하되 전체 제목은 접근 가능한 상세/툴팁으로 확인한다.
- [제안] 진행률·시간·용량에는 폭이 흔들리지 않는 숫자 표시를 사용한다.

### 3.3 간격·형태 — 신규 제안

- 기본 간격 단위: 4px. 주요 간격: 4/8/12/16/24px.
- 컨트롤 높이: 기본 36px, 밀집 도구 32px를 시작점으로 한다. 작은 아이콘도 클릭 영역은 따로 확보한다.
- 모서리: 입력·버튼 6px, 카드 10px, 팝업 12px를 후보값으로 둔다. 상태 배지만 필요한 경우 캡슐형을 쓴다.
- 갤러리 프리셋의 9/13/15px 같은 기존 값은 무조건 반올림하지 않는다. 화면 비교 후 공통 토큰으로 이행한다.
- 창 크기가 줄면 제어부의 높이가 늘 수 있다. 제어부와 결과부의 행 개수를 고정해 결과 영역을 밀어내지 않는다. [E21]

### 3.4 움직임 — E06, E09, E22

- [요구] 미리보기 화살표는 호버 중 확대를 유지하고 해제 시 원복한다. 확대됐다가 호버 중 다시 줄어드는 효과는 금지한다.
- [요구] 작가 폴더는 표지와 같은 크기의 이미지가 가로로 펼쳐지는 동작을 사용한다. 한 작품이면 확대 대신 반짝임으로 반응한다.
- [현행] 화살표는 1.16배 확대, 작가 펼침은 420ms, 반짝임은 620ms를 사용한다. 이 수치는 기존 구현값이며 전역 기본값이 아니다.
- [제안] 일반 색·테두리 전환은 120~180ms, 일반 패널 등장은 160~240ms로 시작한다. 콘텐츠 탐색을 애니메이션 완료까지 막지 않는다.
- [현행/유지] `prefers-reduced-motion`에서는 이동·확대·반짝임을 줄이거나 생략한다. 가림막·로딩 상태·필수 정보까지 사라져서는 안 된다.

## 4. 공통 컴포넌트 계약

### C01. 버튼과 상태별 주 행동

[요구: E05, E12] 미다운로드는 다운로드, 진행·대기 중은 취소, 완료는 체크 표시, 검토 대기는 검토 동작으로 상태를 읽을 수 있어야 한다. 다중선택 취소는 실제 취소 가능한 개수만 표시하며 완료 파일은 건드리지 않는다.

[제안] 기본/호버/포커스/눌림/비활성/처리 중 상태를 모두 명세한다. 비활성 사유를 알 수 있어야 하며 처리 중 중복 명령을 막는다. 주요 영역마다 가장 중요한 행동 하나를 시각적으로 우선하고 위험 동작은 분리한다.

[현행: E27] 설정의 복구·재구축·초기화 버튼은 문구에 맞는 폭과 최소 높이 34px, 안쪽 여백 6px/12px를 사용한다. 설명 영역이 늘어나거나 창이 좁아져도 버튼을 240px/전체 폭으로 강제 확대하지 않는다. 위험 색과 확인 절차는 유지한다.

### C02. 입력·드롭다운·설정 도움말

- [요구: E04, E10] 일반/Hitomi/Danbooru/CHZZK 등 적용 범위를 명확히 구분한다. 공통 기능과 소스별 값의 저장 범위를 혼동하지 않는다.
- [요구] 드롭다운이 주변 다크 UI와 이질적으로 보이지 않아야 한다. 기존 `DropdownSelect`의 toolbar/field 유형을 우선 검토한다.
- [제안] 마우스와 키보드로 열기·선택·닫기가 가능하고, 긴 목록은 메뉴 안에서 스크롤한다. 화면 끝에서는 반대쪽으로 열거나 높이를 제한한다.
- [요구] 기본 설명은 1~2줄. [제안] 보충 설명은 hover뿐 아니라 focus로도 확인하고 Escape로 닫을 수 있다.
- [제안] 저장 실패 때 새 값이 적용된 것처럼 방치하지 않는다. 이전 값 복구 또는 재시도를 명시한다. 오류가 사용자의 입력을 지우지 않는다.

### C03. 툴팁·비모달 패널·확인 모달

| 유형 | 사용 상황 | 배경과 포커스 |

### C04. 알림·오류·활동 기록

- [요구: E17] 반복되는 녹화 시작·종료와 스크린샷 결과는 짧은 비모달 피드백으로 알린다. 사용자 동작과 실제 저장 완료 시점을 구분한다.
- [제안: E20] 공통 초기화 실패 하나가 수십 개 하위 오류 토스트로 번지지 않게 한다. 대표 원인, 사용 불가 범위, 안전한 다음 행동을 한곳에 표시한다.
- [요구/현행: E11, E12] 이번 실행은 전체 대기열이 아니라 최근 활동이다. 최신 50건을 먼저 선택한 뒤, 그 안에서 진행·대기·해시·검증·검토 → 실패·중단 → 완료·취소·격리·중복 처리 완료 순으로 정렬한다. 같은 묶음은 최신순이다.
- [유지] 자동분류 영구 기록은 별도 목록·페이지·확인 상태를 사용한다. 이번 실행의 50건 제한을 영구 기록 삭제로 구현하지 않는다.
- [요구] 목록 밖 작업도 앨범 선택 바와 플로팅 상세에서 취소 가능해야 한다.
- [제안] 활동 제목만으로 작품 구분이 어려운 문제는 미해결 설계 항목이다. 작은 표지+작가+소스 표시를 검토하되 프라이버시·로드 비용과 함께 검증한다. 이번 명세만으로 구현됐다고 보지 않는다.

### C05. 이미지·영상·프라이버시

- [요구: E09, E10] 표시 크기에 맞는 해상도를 사용한다. 목록 영상은 정적 포스터, Danbooru 상세 영상은 로드 후 자동재생 요청을 따른다. 플랫폼이 재생을 차단하면 수동 재생을 제공한다.
- [요구] 다운로드 완료 앨범의 페이지 확대는 로컬 원본을 우선하며 사용자가 창 크기를 조절할 수 있다.
- [현행/유지: E22] 반짝임은 `::before`, 이미지 프라이버시 마스크는 `::after`로 분리돼 있다. 하나의 opacity/animation/display 규칙을 공유하지 않는다.
- [요구] 한 작품 폴더, 여러 작품의 펼침, 상세·페이지·판본 미리보기에도 동일한 프라이버시 보호를 적용한다.
- [현행] 갤러리는 주로 시각 마스크, CHZZK 녹화 보관함은 제목·경로·파일명과 검색 입력도 다룬다. 플랫폼별 보호 범위를 표시한다. 모드를 켜면 모든 정보가 지워지거나 암호화된다고 안내하지 않는다.
- [제안] 로딩/실패/원본 없음/원본 변경을 구분한다. 실패를 영구 스켈레톤으로 숨기지 않는다.

### C06. 처리 중·대기·주의·실패 구분 — E26, 2026-09-23 보완

[요구] 녹화 탭의 ‘목록 준비 중’ 안내가 빨간 오류처럼 보여 정상 작업인지 앱 문제인지 구분하기 어렵다. 색만 바꾸지 말고 기호·문구·완료 시점도 구분한다.

| 상태 | 표시 계약 | 녹화 탭 적용 |
| --- | --- | --- |
| 최초 목록 준비 중 | 청록 회전 표시 + 짧은 작업명. 전체 화면 차단 없음 | `BROWSER_INITIALIZING` 또는 최초 응답 대기. 오류 알림 아님 |
| 확인/작업 대기 | 중립색 + 말줄임 기호 + 대기 사유. 실행 중처럼 회전시키지 않음 | 요약 기록 확인·저장 상태 재확인·병합 대기 |

| 실제 실패 | 빨간 × + 실패한 작업명. 원인·다음 행동을 상세 안내 | 저장소 초기화 실패·요청 실패·녹화/병합 실패 |

- [현행] 녹화 목록 준비 표시는 250ms 이후 노출한다. 빠른 응답과 정상적인 주기 갱신에는 회전 표시를 띄우지 않는다.
- [현행] 준비가 20초를 넘으면 ‘준비가 지연되고 있습니다’로 바꾼다. 시간 경과만으로 실패를 단정하거나 가짜 진행률을 만들지 않는다. 실제 오류 응답이 오면 즉시 주의/실패로 전환한다.
- [현행] 본문은 짧은 상태 한 줄을 기본으로 하고 상세 사유·다른 탭 이용 가능 안내는 정보 아이콘 호버/키보드 포커스로 제공한다. 동작 감소 설정에서는 회전을 생략하되 문구는 유지한다.
- [현행] ‘확인 전 요약 항목’을 임의의 실패로 분류하지 않는다. 캐시된 과거 상태와 현재 검증 결과를 구별한다.
- [범위] CHZZK 녹화 목록·카드에 이어 자동 녹화 목록·내 채널에도 적용했다. 계정 상태 확인의 `BROWSER_INITIALIZING`도 오류로 취급하지 않는다. 앱 시작 안내는 준비 중/상태 확인 실패/실제 시작 실패를 별도 문구·기호로 표시한다. 다른 소스의 모든 로딩/오류 UI가 이 계약으로 전환됐다는 의미는 아니다. [E27, 2026-09-25]

## 5. Atsumi 전용 사용 패턴

### F01. 탐색 → 작가 검색 → 원래 탐색 복귀

[요구: E01] 원래 탐색은 유지한 채 작가 탐색을 별도 컨텍스트로 연다. 각 컨텍스트의 검색·페이지·스크롤·이미 준비한 항목을 보존한다. 새 검색, 기존 탭 재활성화, 페이지 이동을 같은 초기화 동작으로 묶지 않는다.

[요구/현행] Hitomi Auto Find의 페이지당 표시 수는 Hitomi Explore 설정과 연동한다. Danbooru는 별도 값이다. 마지막 행 맞춤은 API 상한과 실제 결과 수 안에서만 수행하며, 끝난 검색을 다른 검색 결과로 채우지 않는다.

[요구: E05] Related 항목을 Ctrl+클릭하면 배경 탭으로 열고 현재 탭·미리보기 위치를 유지한다. 다운로드 완료 여부도 Related에서 식별 가능해야 한다.

### F02. 작가 폴더와 대표 미리보기

- [요구: E07, E09] 폴더를 열지 않아도 대표 표지와 요약 태그를 준비한다. 저장한 후보와 태그를 매번 재탐색하지 않는다.
- [요구] 자동 대표 후보는 다운로드 완료 후 후처리로 갱신하고, 일부 폴더/작품은 사용자가 지정할 수 있게 한다.
- [제안] 사용자 지정은 자동 갱신보다 우선한다. 빈 태그 결과와 아직 모르는 태그를 구분해 무한 재조회를 피한다.
- [요구] 호버 영역은 정보칸이 아니라 표지 영역이다. 여러 작품은 같은 크기로 수평 펼침, 한 작품은 같은 크기에서 반응 효과만 준다. 좁은 화면은 무리하게 축소·화면 밖 표시하지 않고 펼치는 수를 줄인다.
- [주의] 당시 대화의 ‘3번으로 가자’에서 3번 제안 전문은 이 문맥만으로 확정할 수 없다. 자동+일부 수동 지정이라는 명시된 요구만 채택한다. 텍스트 페이지 판별 알고리즘·정확도는 이 문서에서 새로 승인하지 않는다.

### F03. 플로팅 상세와 페이지 미리보기

- [요구: E05] Q/E는 상세 탭, A/D는 추가 미리보기 묶음 또는 열린 PAGE PREVIEW의 페이지 이동에 사용한다.
- [요구] 숫자 입력으로 미리보기 페이지/묶음 위치를 바꿀 수 있다. 범위를 벗어난 입력은 안전하게 처리한다.
- [제안] 키보드 우선순위는 최상위 확인창/페이지 미리보기 → 활성 플로팅 상세 → 기본 목록으로 한다. 한 입력이 두 화면을 동시에 이동시키지 않는다. 입력칸·조합 입력·수정키 사용 중에는 문자 단축키를 가로채지 않는다.
- [요구: E06] 꺾쇠 버튼은 표지 그리드 좌우 중앙 안쪽에 위치하고 별도 배경 없이 외곽선·그림자로 흰 이미지에서도 보인다. 세로 3×3/가로 2열×4행 모두 전체 그리드의 세로 중앙을 기준으로 한다.
- [유지] `?`/`/` 도움말 요구와 검색 입력 내 문자 `/` 입력은 충돌하지 않게 범위를 둔다. CHZZK 플레이어 단축키와 Hitomi 단축키를 함께 실행하지 않는다.

### F04. 판본 비교와 자동분류

- [요구: E13] 기존 앨범 A/신규 앨범 B를 상하 정렬하고 대응·추가 페이지를 구별한다. 라벨 공간을 이미지가 침범하지 않는다.
- [요구] 판본 미리보기 호버 확대는 기존 카드 미리보기 크기 설정과 연계한다. 툴팁·확대 이미지는 화면 안에서 확인할 수 있어야 한다.
- [요구] 긴 정책 설명 대신 결과 요약을 우선한다. 예: ‘B 보존 · A 격리 예정’. 이유·포함률·고유 페이지는 근거 보기로 분리하되 손실 영향은 행동 옆에 남긴다.
- [요구] 기본 수동 선택은 검토 미루기/기존 A 제거/신규 B 제거/오탐 판정/문제 없음이며, 문제 없음은 성공색이다. 완료본 직접 대조 등 다른 검토 유형의 실제 의미를 동일 버튼에 억지로 덮어쓰지 않는다.
- [요구] 사용자가 별도 사유문을 작성하지 않아도 최종 선택을 로컬 판정 자료로 남긴다. 자동 전송을 추가하지 않는다.
- [요구/현행] 자동분류 근거에서 목록에 복원·확인 완료·순차 검토를 제공한다. **목록 복원은 격리 파일 복원과 다르다.**
- [요구/현행: E13 추가] 처리된 A/B 원본이 남아 있으면 검토 전용 읽기로 복원 없이 비교한다. 영구 삭제·변경된 원본은 당시 이미지처럼 제시하지 않는다. 당시 근거 이미지의 별도 보존은 후속 설계다.
- [경계] 자동분류 임계값과 학습 규칙은 [중복 플로우](../DUPLICATE_FLOWS.md)의 영역이다. UI 명세가 임계값을 새로 정하지 않는다.

### F05. Auto Find의 근거와 분류

[요구/현행: E23] 작가와 그룹은 독립된 탐색 조건이다. 합동지는 즐겨찾기된 참여 작가/그룹의 각 분류에 보이지만 전체 수·선택·다운로드 명령은 동일 앨범을 중복 계산하지 않는다. 그룹만으로 작가를 추정하지 않는다.

[요구/현행] 기본 탐색 범위는 가장 최근 보유 작품 이후다. 현재 계약의 기준은 대상별 검증된 소유본의 최대 gallery ID이며 ‘최근 본 작품’ 또는 ‘최근 다운로드 날짜’가 아니다. 보유본이 없으면 전체 범위이며 별도 전체 기록 옵션도 유지한다.

[제안] 지난 실행 결과와 새 설정이 다르면 ‘다음 갱신부터 적용’처럼 알린다. 과거 결과의 기준을 새 기준인 것처럼 바꿔 표시하지 않는다. 세부 계약은 [Auto Find 명세](../AUTO_FIND_TARGET_DISCOVERY.md)를 따른다.

### F06. CHZZK의 단일 시청 진입과 독립 녹화

- [요구: E14~E17] 실시간 시청은 라이브 탭에서 시작한다. 내 채널에는 즐겨찾기/예약을 채널 ID로 합쳐 한 번만 표시한다.
- [요구] 채널 프로필+채널명+상태를 묶은 배너를 사용하고 즐겨찾기는 주황색으로 구별한다. 두 열을 기본 방향으로 하되 좁으면 한 열로 바꾼다.
- [요구] URL 입력도 같은 채널의 기존 수신을 확인한다. 화면 경로가 다르다고 같은 방송을 별도로 수신하지 않는다.
- [요구] 시청 종료·음소거·배치 변경·탭 전환과 녹화 중지를 구별한다. 별표는 예약/녹화 상태를 바꾸지 않는다. 각 방송은 기존 볼륨 UI로 독립 조절한다.
- [요구] 배속은 한 메뉴로 모으고 중복된 진입을 제거한다. 스크린샷은 명령 시점 프레임 확보 후 백그라운드 저장하며 실패를 완료로 알리지 않는다.
- [현행/한계] 장시간 일시정지 등 원본 플레이어 수신 특성까지 모두 녹화와 독립된 것은 아니다. 실제 가능한 범위 이상을 UI가 보장하지 않는다.
- [요구/제안: E24] 녹화 중단 구간을 날짜만으로 서로 다른 방송처럼 펼치지 않는다. 채널+방송 회차 식별을 기준으로 묶는 방향을 유지하되 실제 구현·이행 범위는 별도 확인한다. 영상 삭제 기록과 보존된 오류 로그를 분리한다.

## 6. 비기능 UX와 자원 예산

- [요구: E18] 앱 시작 2초 이내가 목표다. [현행 문서] 프로세스 시작부터 실제 입력 가능한 화면까지 계측한다. OS 실행 대기, 재부팅 후 첫 실행, 반복 실행을 나눠 보고한다. 목표가 달성됐다고 이번 문서에서 선언하지 않는다.
- [요구: E01] 500MB~1GB 허용은 당시 탐색 캐시 논의의 수용 범위다. **현재 전체 앱·멀티뷰 영상·녹화까지 포함한 확정 RAM 상한으로 확대 해석하지 않는다.**
- [제안] 탐색 캐시 예산, 디코딩 이미지 메모리, 영상 메모리, 백그라운드 작업 예산은 분리 계측한다. 압축 파일 크기를 RAM 사용량으로 간주하지 않는다.
- [요구/제안: E07, E08, E18] 작가 폴더 표지·태그 준비 요구는 유지하되 첫 입력을 막는 전량 동시 로드로 구현하지 않는다. 요약/현재 화면 → 근처 미리보기 → 미방문 폴더 예열 순서로 처리한다.
- [요구: E08] 설정에서 캐시와 다운로드 사용량을 구분한다. 디스크 전체/남은 공간을 알 수 있으면 표시하고, 계산 중·알 수 없음은 0으로 표시하지 않는다.
- [제안: E20] DB 버전 불일치 같은 실행 불가는 버전·원인·안전한 다음 행동을 요약한다. 데이터 초기화를 일반적인 해결 버튼으로 권하지 않는다.

### 1차 구현 계획 — 이번 작업에서는 실행하지 않음

1. **명세 검토:** 제품 원칙, 후속 결정, 제안 수치, 프라이버시 범위를 확인한다.
2. **토큰 정리:** 기존 Ink와 갤러리 프리셋을 기준으로 중복 정의를 조사한다. 기능별 예외를 먼저 기록하고 일괄 치환하지 않는다.
3. **컴포넌트 카탈로그:** 실제 React 컴포넌트로 버튼/입력/드롭다운/툴팁/상태/로딩을 한곳에 전시한다. 비활성·오류·긴 제목·프라이버시·reduced-motion 상태도 제공한다.
4. **대표 화면 검증:** Explore와 설정에 먼저 적용하고, 플로팅 상세·판본 검토·활동 기록을 검증한다. CHZZK는 별도 네이티브 입력 검증 후 적용한다.
5. **점진 확장:** 밝은/시스템 테마, 활동 표지, 녹화 회차 묶음, 과거 판정 이미지 보존은 개별 범위를 정해 수행한다.

## 9. 변경 관리

공통 토큰·컴포넌트를 바꿀 때 영향받는 소스와 화면을 적는다. 새 예외는 근거·범위·제거 조건을 남긴다. 사용자 결정이 바뀌면 이전 항목을 지우지 말고 ‘대체됨/보완됨’으로 연결한다.

작업 장소는 현재 공유 작업 트리 `2849`다. 다른 대화의 변경을 먼저 확인하고, 명세 편집을 이유로 새 worktree 생성·동기화·커밋·푸시·릴리즈·사용자 데이터 변경을 수행하지 않는다. [E25, AGENTS.md]

향후 구현 완료 보고에는 ‘소스 반영 / 테스트 / 개발 빌드 / 실행 확인 / 릴리즈’를 구분한다. 사용자가 어느 앱에서 변경을 확인할 수 있는지 명확하게 안내한다.
