# Windows 로그인 시 자동 실행

설정 → 일반 → **Windows 로그인 시 자동 실행**에서 켜거나 끈다.
스위치는 저장 버튼과 별개로 즉시 적용되며, 설정을 열거나 앱을 실행하는 것만으로 켜지지 않는다.
PC의 전원 투입 시점이 아니라 현재 Windows 계정으로 로그인한 뒤 실행된다.

## 등록과 실행 대상

- 현재 사용자의 시작 프로그램 폴더에 Atsumi 소유 바로가기를 등록한다. 관리자 권한은 필요 없다.
- 개발 빌드는 컴파일한 워크스페이스의 `tools/start_debug_app_hidden.ps1`을 사용한다. Vite 없이 debug EXE만 실행하지 않는다.
- 배포 빌드는 현재 실행 중인 설치본의 EXE를 사용한다.
- 끄면 이 기능이 만든 시작 프로그램 바로가기만 제거한다. 바탕화면 바로가기, DB, 다운로드, 다른 시작 프로그램은 변경하지 않는다.
- DB의 복제된 boolean 대신 실제 바로가기 상태를 조회한다. 이전 경로로 등록된 경우 설정에서 현재 앱으로 다시 연결할 수 있다.
- 동일 이름의 외부 바로가기는 덮어쓰거나 삭제하지 않는다.

Windows 설정/작업 관리자에서 별도로 차단했다면 앱에 등록되어 있어도 시작하지 않을 수 있다.
이 경우 앱에서 경고하고 Windows **설정 → 앱 → 시작 프로그램**에서 사용하도록 안내한다.
Windows의 비공개 승인 레지스트리는 읽기만 하며, 알려지지 않은 상태를 정상 실행으로 간주하거나 임의로 덮어쓰지 않는다.

## 검증 경계

자동화 테스트는 임시 폴더의 바로가기를 대상으로 수행한다. 개발 중 테스트를 위해 실제 사용자의 자동 실행을 켜지 않는다.
브라우저 미리보기에서는 지원하지 않는 기능으로 표시한다.
Windows 로그인 후 실제 실행 확인은 사용자가 기능을 켠 뒤 다음 로그인에서 수행해야 한다.

참고: [Microsoft Shell Links](https://learn.microsoft.com/en-us/windows/win32/shell/links),
[Run 키 명령 길이 제한](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).
긴 개발 실행기 명령을 보존하기 위해 Run 키 대신 바로가기를 사용한다.
