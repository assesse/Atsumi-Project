# 검색 정렬과 활동 상태 점검

2026년 10월 3일 기준 Atsumi 2.0.0 소스에서 앱이 노출하거나 생성하는 Hitomi와 Danbooru의 검색 조건 및 정렬 옵션을 조사했다. 공식 사이트의 모든 고급 기능을 앱이 지원한다는 뜻은 아니다. 아래 표는 현재 앱의 지원 범위 전체와 공식 기능 사이의 차이를 정리한다.

인기순은 실제 기능이다. 그러나 정렬 인자가 존재하는 것과 앱이 결과를 정확히 유지하는 것은 별개이며, Hitomi의 다국어 인기순과 재정렬, 일부 검색 문법에 구현상 차이가 있다. 이번 작업은 검색 옵션에 대한 조사와 사용자 요청 3~6번의 화면 수정이며, 검색 엔진의 미지원 기능을 일괄 추가하지는 않는다. 원격 진단은 후속 답변에 따라 설계 검토까지만 수행하고 서버 전송을 활성화하지 않았다.

## 공식 근거와 검증 범위

- [Hitomi 검색 화면](https://hitomi.la/search.html)의 실제 HTML에서 Date Added, Date Published, Popular Today/Week/Month/Year, Random 옵션을 확인했다.
- 해당 화면이 참조하는 [공식 results.js](https://ltn.gold-usergeneratedcontent.net/results.js)와 [공식 search.js](https://ltn.gold-usergeneratedcontent.net/search.js)를 읽어 검색어 해석, OR, 정렬, 인덱스 주소 구성을 대조했다. 미디어 파일을 수집하지 않았다.
- [Danbooru 공식 검색 도움말](https://safebooru.donmai.us/wiki_pages/help:cheatsheet)과 [공식 PostQuery 구현](https://github.com/danbooru/danbooru/blob/master/app/logical/post_query.rb)을 대조했다. Safebooru는 이 문서를 제공하는 공식 donmai.us 사이트다. 앱의 접속 대상을 Safebooru로 변경한 것은 아니다.
- Danbooru 사이트 연결 장애와 검색 문법 검증은 별개다. 앞선 실제 PC 점검에서는 danbooru.donmai.us의 TLS 연결이 재설정됐다. 따라서 아래의 공식 지원 판정은 모든 검색 조합을 이 PC의 실서버에서 성공시켰다는 의미가 아니다.

## Hitomi 정렬 전체

| 앱 옵션 | 원본 사이트 대응 | 앱 동작 및 판정 |
|---|---|---|
| 최신순 `recent` | Date Added | `n/index-{language}.nozomi`를 읽고 ID 내림차순으로 배열한다. 화면에서는 다시 `publishedAt` 기준으로 정렬한다. 이 값은 원본 `galleryinfo.date`에서 만든 날짜로, 원본 인덱스 순서 보존과는 다르다. 재정렬 제거 권고. |
| 인기순 오늘 | Popular Today | `n/popular/today-{language}.nozomi`. 실제 인기 인덱스를 사용한다. |
| 인기순 이번 주 | Popular Week | `n/popular/week-{language}.nozomi`. 실제 지원. |
| 인기순 이번 달 | Popular Month | `n/popular/month-{language}.nozomi`. 실제 지원. |
| 인기순 올해 | Popular Year | `n/popular/year-{language}.nozomi`. 실제 지원. |
| 무작위 | Random | 전체 후보 인덱스에 검색 조건을 적용한 뒤 요청별 임의 시드로 섞는다. 같은 검색 탭은 재사용하므로 새로고침 전에는 같은 결과가 유지된다. 화면의 별도 고정 해시 정렬은 제거 권고. |
| 앱에 없는 정렬 | Date Published | 공식 사이트는 별도 제공하지만 앱에는 독립 옵션이 없다. |

인기 지표의 원래 산식이나 정확한 집계 경계는 이번 공식 프런트엔드 코드만으로 확정할 수 없다. 따라서 Week/Month/Year를 한국 시간의 이번 주·이번 달·올해와 동일하게 단정하지 말고, 주간·월간·연간이라는 표기가 더 안전하다.

현재 다국어 인기순은 각 언어의 순위 목록을 차례로 이어 붙인다. 따라서 한국어와 일본어를 함께 선택한 결과는 두 언어 전체의 통합 인기순이 아니다. 해결책은 전체 언어 인기 인덱스를 기준 순서로 삼고 선택한 언어의 ID 집합으로 필터링하는 것이다.

또한 화면의 `score`는 실제 조회수나 투표 점수가 아니라 이번 검색의 순위에서 만들어 낸 숫자다. 같은 앨범을 다른 검색으로 읽으면 공용 갤러리 Map의 점수가 덮어써질 수 있다. 검색 탭의 원본 ID 순서를 보존하고, 검색별 순위를 메타데이터 캐시와 분리하는 것이 맞다.

다운로드 탭의 일간·주간·월간·연간 인기순은 `n/popular/{period}-all.nozomi`의 전체 순위와 보유 앨범을 대조한다. 24시간 캐시가 있으며 갱신 실패 시 기존 순위를 사용하고, 순위가 없는 앨범은 뒤로 보낸다. Explore의 다국어 목록 연결 문제와는 다른 경로다.

## Hitomi 검색 조건 전체

| 조건 | 현재 앱 처리 | 판정 |
|---|---|---|
| 일반 검색어 | 공식 galleries 인덱스에서 후보를 찾고 화면에서 메타데이터 문자열로 재필터링 | 원본 인덱스와 화면의 부분 문자열 조건이 다르므로 결과가 추가로 사라질 수 있다. 한글 입력 자체를 금지하지는 않는다. |
| 여러 조건 공백 연결 | 각 인덱스의 교집합 | AND 지원. |
| 앞에 `-` | 해당 인덱스의 차집합 또는 부정 검색어 | 제외 조건 지원. |
| 단어 사이 `_` | 공백으로 정규화 | 지원. |
| `artist:` | 작가 인덱스 | 지원. |
| `group:` | 그룹 인덱스 | 지원. 단, 화면 메타데이터는 첫 그룹 중심이므로 여러 그룹의 정확한 결과 보존은 추가 보완 필요. |
| `series:` | 시리즈 인덱스 | 지원. |
| `character:` | 캐릭터 인덱스 | 지원. |
| `female:` / `male:` | 성별 네임스페이스 태그 인덱스 | 지원. |
| `tag:` | 일반 태그 인덱스 | 지원. |
| 언어 버튼 | 한국어·일본어·중국어·영어 중 선택 | 앱의 지원 언어는 네 가지. 빈 선택은 백엔드에서는 한국어 기본값인데 화면에서는 아무 언어도 허용하지 않아 불일치한다. |
| 검색창 `language:` | 백엔드에서 구조화 조건으로 인식하지 못하고 일반 검색어로 처리 | 공식 사이트에는 있으나 앱 지원 불완전. 언어 버튼과 구분해야 한다. |
| 검색창 `type:` | 일반 검색어로 처리 | 공식 사이트에는 있으나 앱 지원 불완전. |
| `orderby:` / `sortby:` 및 key/direction | 일반 검색어로 처리 | 공식 문법은 존재하지만 앱은 드롭다운만 정상 경로로 취급한다. |
| `or` | AND 검색의 일반 단어로 취급 | 현재 공식 사이트의 OR 처리와 불일치. |
| 숫자만 7자리 | 단일 gallery ID | 앱 자체 단축 문법. 언어 필터는 우회하지만 전역 필수/제외 태그까지 무시하는 것은 아니다. 다른 자릿수 전체를 ID로 인식하는 기능은 아니다. |
| 설정의 필수/제외 태그 | 각 검색에 포함/제외 태그를 추가 | 태그 인덱스용 조건이다. 임의의 `artist:` 같은 문법을 넣는 만능 검색어 칸은 아니다. |
| 페이지당 앨범 수 | 1~200 검증 | 앱의 페이징 옵션이며 공식 사이트의 고정 표시 수와 독립적이다. |

검색 후보는 기본 설정에서 조건 적용 후 최대 1,000개로 제한된다. 이 제한은 페이지당 표시 수와 다르며, 앱의 전체 페이지 수를 사이트 전체 작품 수로 해석하면 안 된다.

후속 수정 권고는 ① 서버 결과 순서 및 멤버십 보존, ② 다국어 통합 인기순, ③ 언어·유형·OR·정렬 문법의 명시적 파싱 또는 미지원 오류 표시, ④ 빈 언어 선택과 후보 수 제한의 안내 순서다. 이번에는 조사 요청 범위를 넘어 이 검색 정책들을 일괄 변경하지 않았다.

## Danbooru 정렬 전체

| 앱 옵션 | 생성하는 인자 | 공식 지원 및 의미 |
|---|---|---|
| 최신 등록순 | 별도 인자 없음 | 기본 ID 역순. 지원. |
| 오래된 등록순 | `order:id_asc` | 지원. |
| 점수 높은순 | `order:score` | 지원. 최근성 가중 인기순과는 다르다. |
| 즐겨찾기 많은순 | `order:favcount` | 지원. |
| 해상도 높은순 | `order:mpixels` | 지원. 전체 픽셀 수 기준. |
| 파일 큰순 | `order:filesize` | 지원. |
| 태그 많은순 | `order:tagcount` | 지원. |
| 세로 이미지 우선 | `order:portrait` | 지원. 세로로 긴 비율부터 정렬하며 세로 이미지만 고르는 필터는 아니다. |
| 가로 이미지 우선 | `order:landscape` | 지원. 가로로 긴 비율부터 정렬한다. |
| 앱 드롭다운에 없는 인기순 | `order:rank` | 공식 기능이다. 앱의 점수순과 동일하지 않다. 검색창 직접 입력은 일반 최신순 드롭다운 상태에서 가능하다. |

## Danbooru 검색 조건 전체

| 앱 조건 | 생성 인자 | 판정 |
|---|---|---|
| 일반 태그·제외 태그 | 입력문 전달 | 공식 문법 지원. 다만 앱의 사전 태그 개수 계산은 단순 공백 분리여서 OR·괄호·따옴표 문법을 과도하게 차단할 수 있다. |
| 등급 g/s/q/e | `rating:` 및 쉼표 연결 | 실제 조건. |
| jpg/png/gif/webp/avif/webm/mp4/zip | `filetype:` 및 쉼표 연결 | 실제 파일형식 조건. zip은 Ugoira 계열 선택에 사용한다. |
| 시작/종료일 | `date:>=`, `date:<=`, `date:시작..종료` | 실제 조건. 앱의 날짜 검사는 형식 중심이며 역전된 기간 검증이 부족하다. |
| 최소 점수 | `score:>=` | 실제 조건. |
| 최소 즐겨찾기 수 | `favcount:>=` | 실제 조건. |
| 부모 있음/없음 | `parent:any`, `parent:none` | 실제 조건. |
| 자식 있음/없음 | `child:any`, `child:none` | 실제 조건. |
| 숫자만 입력 | 해당 post 직접 조회 | 앱 단축 문법. 나머지 상세 필터를 적용하지 않는다. |
| 페이지당 개수 | API `limit` | 앱은 최대 100으로 제한하며 서버 문서상 최대값 200보다 보수적이다. |

비로그인 검색의 제한 대상 조건은 2개이고, `order:`는 이 개수에 포함된다. 따라서 일반 태그 두 개에 정렬을 추가하면 제한 대상이 세 개가 된다. 등급·날짜·점수 등의 무료 metatag 목록은 현재 공식 PostQuery의 목록과 일치한다.

추가로 확인한 앱 조합 오류는 다음과 같다.

- 검색창에 이미 `order:`를 입력했어도 드롭다운 정렬을 덧붙일 수 있다. 원본 서버의 단일 정렬 조건과 충돌한다. 같은 종류의 날짜·등급 필터도 충돌 가능하다.
- 등급 또는 파일형식을 전부 해제하면 조건을 생략한다. 따라서 사용자는 아무것도 선택하지 않았는데 서버에는 전체 허용으로 요청한다.
- 숫자 전용 검색은 상세 필터를 우회한다. 버그로 단정하기보다 UI에 예외를 설명해야 한다.
- 기간 + 점수순은 해당 기간의 점수순이지, 공식 `order:rank`와 같은 알고리즘이 아니다.

## 이번에 수정한 화면 동작

- Explore 검색 탭은 제출 당시 언어·정렬 조건을 유지한다. 다른 검색을 준비하는 동안 편집한 필터로 이전 탭의 조건을 덮어쓰지 않는다. 한국어 → 일본어 → 한국어 복귀 시 기존 결과를 다시 표시하고 불필요한 서버 검색은 하지 않는다.
- Hitomi 앨범 카드의 일반 더블클릭은 Explore·Auto Find·Downloads 모두 상세보기를 연다. Ctrl/Shift 클릭의 다중 선택과 기존 우클릭·키보드 작업은 유지한다.
- 한 장 선택 시 강조는 유지하지만 체크박스는 표시하지 않는다. Ctrl/Shift로 두 장 이상 선택하면 체크박스가 나타난다. 다시 한 장만 남으면 숨긴다. 국기도 체크박스가 나타날 때만 옆으로 움직인다.
- 활동 패널의 상태 막대는 5px에서 10px로, 활동 버튼의 진행 테두리는 2px에서 4px로 변경했다.
- 전체 진행 표시는 성공한 다운로드 비율이 아니라 자동 처리가 종료된 작업의 비율이다. 검토 대기·중단·실패·취소·격리도 종료분에 포함하되 상태별 색과 개수는 구분한다. 남은 작업이 있는데 반올림으로 100%가 되지 않게 했다. 실제 파일 수신량이나 DB 상태를 100% 완료로 조작하지 않는다.
- 수신 후 단계에는 `중복 비교·검증` 또는 `최종 저장·검증`과 수신율을 함께 표시한다. 파일을 다 받았다는 사실과 전체 작업 완료를 구분한다.

## 다운로드 큐와 실시간 실행의 의미

두 화면은 프로세스를 보관하는 별도의 실행기가 아니라 같은 다운로드 시스템의 서로 다른 조회 화면이다.

| 화면 | 포함하는 대상 | 제외하거나 제한하는 대상 |
|---|---|---|
| 다운로드 큐 | DB 기준 queued, resolving_metadata, downloading, hashing, verifying, retry_wait | completed, review_required, failed, interrupted, cancelled, quarantined는 기본 목록에서 제외. 이전 실행에서 이어받은 작업도 현재 활성 상태라면 포함. |
| 실시간 실행 | 이번 화면 세션이 관찰한 Hitomi 다운로드 변화, 자동 판본 분류, Danbooru 저장 활동 | 최근 50건을 표시. 실행 중인 작업만이 아니라 완료·중단·검토 대기도 포함. 모든 과거 작업의 영구 이력 화면은 아님. |

다운로드 큐는 한 번에 100개 단위의 DB 조회와 5초 주기 갱신을 사용한다. 실시간 실행은 이벤트 기반 목록이다. 이름만으로 차이가 명확하지 않아 화면에도 짧은 설명을 추가했다.

## 수신 100퍼센트 이후의 작업

파일 수신 뒤에는 해시/검증 대기, 같은 작가의 판본 처리 충돌을 막는 잠금 대기, 파일 무결성 확인, 기존 앨범과 중복 비교, 자동 분류 또는 수동 검토 전환, 최종 manifest 저장과 재검증이 이어진다. 이 과정은 파일 수신율이 100%여도 아직 끝나지 않을 수 있다. 현재 `hashing` 한 상태에 여러 후처리 단계가 묶여 있어 초 단위의 정확한 내부 단계는 이 상태 이름만으로 알 수 없다.

취소 명령은 허용된 상태를 `cancelled`로 바꿀 뿐 `completed`로 바꾸지 않는다. 이미 완료된 항목에 대한 취소는 `INVALID_DOWNLOAD_STATE`로 거절되고, 화면이 목록을 다시 읽는다. 따라서 취소를 누른 뒤 완료로 바뀐 현상은 이미 끝난 작업의 오래된 표시가 새로 반영된 상황과 부합한다. 사용자가 본 당시 항목 ID와 시각이 없어 해당 사건을 확정한 것은 아니다.

이번 읽기 전용 DB 점검에서 download_jobs와 download_entries에 queued/downloading/hashing/verifying 등의 활성 상태는 없었다. 과거 수신 100% 항목이 남았던 시점의 정확한 상태는 재현 또는 단계별 로그가 필요하다. 이벤트 전달이 유실됐을 때 일부 작업만 재조회하는 보정과 세부 단계의 경과시간 계측이 후속 개선 후보다.

## 검증과 적용 상태

언어 전환 캐시 복원, Ctrl/Shift 선택과 더블클릭, 취소·검토가 섞인 종료율, 100% 후처리 표시를 회귀 테스트로 확인한다. 사용자 DB를 수정하거나 다운로드를 재시도하지 않았다. 이번 수정은 개발 작업 폴더의 소스이며, 실행 중인 설치형 릴리즈를 종료·교체하거나 커밋·푸시·배포하지 않았다.

검증 결과는 타입 검사 및 프런트엔드 빌드 통과, 일반 프런트엔드 테스트 1,360개 통과다. Edge headless가 측정 DOM을 반환하지 않아 실패한 레이아웃 12개는 지원되는 Chrome의 별도 오프라인 프로필로 재실행하여 모두 통과했다. Edge 자동 측정의 실패 원인 자체는 이번 변경 범위에서 확정하지 않았다. 합계 1,372개의 테스트를 위 두 실행 결과로 확인했다.

취소 의미에 관한 백엔드 검증은 기존 2.0 테스트 실행 파일에서 상태 전환, 취소의 원자성·멱등성, 완료 항목이 포함된 취소 거부 테스트 3개를 다시 실행해 통과했다. 이번에는 Rust 소스를 변경하지 않았으며 Rust 전체를 새로 빌드해 검사한 것은 아니다.
